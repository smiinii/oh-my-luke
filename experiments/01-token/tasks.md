# 과제와 판정

Java 21의 작은 주문 라이브러리를 사용한다. 각 작업공간은 `fixtures/common`에 과제별 overlay와 동일한 Gradle Wrapper를 복사해 만든다. `tasks/*.json`의 목표가 TASK.md로 세 방식에 똑같이 전달된다.

## 공통 조건

- 상품 금액·단가: 0~1,000,000,000원. 주문 수량: 1~99. 할인은 0~Long.MAX_VALUE와 음수 거부를 평가한다.
- Gradle 설정·Wrapper·TASK 문서·기존 PublicChecks는 변경하지 않는다. 세 방식 모두 같은 제약이다.
- Java 소스는 `benchmark.order` 패키지에 둔다. 기존 공개 API를 삭제하지 않는다.
- 회귀 테스트는 새 `*Checks.java`의 `main`으로 추가한다. `PublicChecks.equal`을 사용하거나 직접 예외로 실패를 표시할 수 있다.
- 외부 테스트 의존성 없이 `./gradlew test`에서 모든 Checks를 실행한다. 라이브러리 다운로드·프레임워크 차이가 비교에 섞이지 않게 했다.
- 최종 평가기는 동일한 소스를 별도 사본에서 `javac --release 21 -proc:none`으로 컴파일한다. 공개 테스트·Java 관측기를 실행하고 기대값과 최종 판정은 외부 Python에서 비교한다. 후보가 수정한 빌드 스크립트는 실행하지 않는다.
- 기존 파일 삭제, 고정 파일 변경, 심볼릭 링크·하드링크·특수 파일, 허용 영역 밖 추가 파일을 거부한다. 파일 500개·단일 2 MB·합계 16 MB·트리 항목 2,000개·깊이 32 이내이며 평가 JVM 한도는 heap 256 MiB, metaspace 128 MiB, 총 평가 시간 120초다.

## A — 무료 배송 경계값

시작 코드의 `OrderCalculator.shippingFee`는 `subtotal > 50_000`일 때만 무료다.

요청: 50,000원 **이상** 무료로 수정하고 경계값 회귀 테스트를 추가한다. 기존 API와 다른 구간 동작을 유지한다.

| 금액 | 배송비 |
|---:|---:|
| 0 / 49,999 | 3,000 |
| 50,000 / 50,001 | 0 |

추가 테스트가 실제 경계값 버그를 잡는지도 검사한다. 최종 코드에서 테스트가 통과한 뒤, 별도 평가 사본의 계산기를 원본 버그로 바꿨을 때 추가 테스트가 실패해야 한다. 빈 테스트는 실패 처리한다.

## B — 정액 할인

시작 코드는 정상 배송비와 `total(long subtotal)`만 제공한다. 다음 API와 테스트를 추가한다.

```java
public long total(long subtotal, long discountAmount)
```

상품 금액만 할인하고 무료 배송 기준은 할인 전 금액이다. 할인 상한은 상품 금액이며 음수 입력은 IllegalArgumentException으로 거부한다. 기존 단일 인자 API를 유지한다.

| 상품 금액 | 할인액 | 결제 금액 |
|---:|---:|---:|
| 40,000 | 5,000 | 38,000 |
| 50,000 | 5,000 | 45,000 |
| 10,000 | 20,000 | 3,000 |
| 0 | 0 | 3,000 |

할인 0, 같은 금액, 초과 할인, 큰 할인, 음수를 포함한다. 할인을 무시하는 변형 구현에서 추가 테스트가 실패해야 한다.

## C — 중복 검증 추출

`CheckoutService.checkout`과 `QuoteService.quote`가 같은 검증을 각각 수행한다. `OrderLineValidator.validate(OrderLine)`를 만들고 두 서비스가 사용하게 한다.

| 입력 | 예외 메시지 |
|---|---|
| null | line is required |
| 음수 단가 | unitPrice must be non-negative |
| 수량 1 미만 또는 99 초과 | quantity must be between 1 and 99 |

예외 종류·메시지·검증 순서와 정상 계산 결과를 유지한다. 단가와 수량이 모두 잘못됐으면 단가 오류가 먼저 발생해야 한다.

테스트 외에 JDK `javap`로 실제 클래스 바이트코드에서 공통 검증기 호출과 서비스의 검증 분기 제거를 확인한다. 주석에 호출 문구만 추가한 구현은 통과하지 않는다. 현재 구조 조건은 이 작은 서비스 클래스에 한정된다.

## 별도 연습 과제

`QuantityLabel.label(1)`은 `item`, 나머지 0~99 수량은 `items`를 반환해야 한다. 시작 코드는 전부 `items`다. A·B·C와 분리하여 예비 계측 확인에만 사용한다.

## 평가 범위의 한계

유한한 검사 사례와 변형 테스트는 모든 프로그램의 정확성을 증명하지 않는다. 테스트·판정 범위를 그대로 공개하고 평가기를 속이는 임의의 악성 JVM 프로그램까지 완전히 판별한다고 주장하지 않는다.

기준 구현은 `references/`, 고정 검사기는 `evaluator/`에 있고 준비 테스트에서만 사용한다. 실험 작업공간에는 복사하지 않으며 로컬 원본 저장소와 Git 공통 디렉터리 접근도 차단한다. 원격 공개 저장소를 통한 재접근 문제는 [격리 계약](measurement.md)의 실제 실험 진입 조건을 따른다.
