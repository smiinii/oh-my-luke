# 격리·계측·비교 계약

## 고정할 것

시작 커밋, 공통 요청, 공개 테스트, 모델, 추론 강도, 실행기 버전·모드, 권한, 제한 시간과 평가기를 고정한다. 드라이런 manifest에는 시작 커밋과 도구·검사기·과제·기준 구현의 SHA-256을 기록한다.

실행 순서는 과제·반복별 순환 배치로 세 도구가 1·2·3번째에 고르게 놓이게 한다. 공급자 캐시와 모델의 비결정성은 제거할 수 없으므로 캐시 토큰·변동 범위를 보고한다.

## 로컬 파일 격리

- 각 실행은 별도 작업 디렉터리와 독립 `.git`을 사용한다. Git worktree를 공유하지 않는다.
- 상대·이전 실행과 평가 공간의 상위 디렉터리를 숨기고 자기 worker 디렉터리만 허용한다.
- 원본 실험 저장소와 Git 공통 디렉터리, 호스트의 `.codex`, `.ssh`, `.aws`, `.config/gh`, `.npmrc`, `.netrc`도 숨긴다.
- 다른 공통 파일의 읽기와 네트워크는 허용하고, 쓰기는 해당 worker의 작업공간·임시 HOME·캐시로 한정한다.
- macOS는 Seatbelt 규칙, Linux는 bubblewrap mount·PID namespace를 사용한다. 샌드박스 미설치·실행 실패 시 우회하지 않는다.
- OS 테스트로 직접 경로·상대 경로·심볼릭 링크·자식 프로세스의 상대 파일 읽기 실패, 공통 파일·로컬 HTTP 접근 성공, 외부 쓰기 차단을 확인한다.

이것은 로컬 파일시스템 격리다. 같은 사용자로 이미 실행 중인 MCP/소켓 서비스나 원격 저장소가 파일을 대신 읽어 주는 경로까지 막았다는 뜻은 아니다.

**실제 실행 전 추가 조건:** 인증은 모델에 비밀값을 주지 않는 공식 경로로 연결하고, MCP 및 원격 접근도 같은 경계에서 동작해야 한다. 공개 GitHub의 기준 구현·상대 결과 재다운로드 경로까지 다룬 실행 환경이 확정되기 전에는 실제 실험을 허용하지 않는다. 외부 문서 사용은 유지하되 이 실험의 정답·상대 결과를 얻는 경로를 차단/감사해야 한다. 현재 preflight는 이 때문에도 `liveReady: false`다.

## 프로세스·시간

단조 시계로 작업 시간을 측정하고 최종 평가 시간은 별도 `judgeMillis`로 기록한다. 기본 한도는 1,200초이며 출력 크기도 제한한다.

일반 자식은 부모의 정상 종료·실패·시간 초과 모두에서 정리한다. Linux는 PID namespace 종료로 분리된 자식까지 수명을 제한한다. macOS의 프로세스 그룹은 `setsid`로 분리된 자식을 완전히 포함하지 못하므로 현재 드라이런 검증에만 사용한다. 실험 본 실행은 Linux PID namespace 환경을 우선 검증한다.

## 토큰 입력 계약

`usage.summarize`는 신뢰하는 실행 관리자가 만든 세션 목록과 원시 로그를 받는다. 모델이 자기 사용량이나 세션 목록을 선언한 값을 신뢰하지 않는다.

세션별로 id, parentId, schema, log 경로·SHA-256, scope를 기록한다.

- `scope=self`: 해당 세션만 집계한다.
- `scope=subtree`: 하위 사용량이 이미 포함됐다는 근거가 있는 경우다. 자식 수치를 다시 합산하지 않는다.
- 포함 관계 또는 세션 목록의 완전성을 모르면 전체 사용량은 null이다.
- 같은 세션 중복 기록은 제거하고, 서로 충돌하는 기록·동일 로그를 다른 세션으로 등록한 경우는 불완전으로 처리한다.
- exec JSONL은 session id와 turn 시작/완료를 확인한다. 같은 종료 이벤트 재전송과 별도 턴을 구분한다.
- 누적 token_count는 세션 메타데이터, 실행 직전 카운터와 최종 경계 검증이 필요하다. 포크에 복사된 부모 사용량은 시작 카운터로 제외한다.
- 실패·미완료 턴, 초기값 없는 포크, 카운터 리셋, 미지원 형식은 정확한 총량으로 발표하지 않는다.
- 이후 턴 실패나 잘린 JSON 로그가 있어도 앞서 완료된 턴의 관측값은 `knownRecordedTokens`에 보존한다. 정확한 총량은 여전히 null이다.

입력+출력만 총토큰에 더한다. 캐시 입력과 추론 출력은 하위 항목이다. 선택적 세부 항목이 미보고면 null로 보존한다. CLI 실행 횟수와 모델 요청 횟수는 다르며 관측되지 않는 모델 요청 횟수는 null이다.

실제 Codex exec 형식은 [OpenAI 비대화형 모드 문서](https://learn.chatgpt.com/docs/non-interactive-mode)를 참고했다. 누적 로그·OMX 자식 목록은 실제 버전별 샘플을 예비 실험에서 대조해야 하며, 현재 합성 샘플 테스트로 실제 스키마 호환성을 단정하지 않는다.

## 결과 해석

- 계획표에 없는 실행, 같은 runId 중복, 다른 protocol/시작 커밋, 합성·실측 혼합을 거부한다.
- 미실행·실패·시간 초과·환경 오류·토큰 누락을 그대로 남긴다. 누락 토큰을 0으로 채우지 않는다.
- 과제별 성공/계획 건수, 전체 토큰 중앙값·범위, 성공 실행 토큰 중앙값, 시간과 누락 건수를 함께 표시한다.
- 절감률은 같은 과제·반복에서 두 방식 모두 성공하고 계측이 완전한 쌍만 사용한다. 비교 가능한 쌍 수를 반드시 표시한다.
- 실패 소비량까지 포함한 전체 소비/성공 건수는 미실행·누락이 있거나 성공이 0건이면 계산하지 않는다.
- 3과제의 초기 비교를 전체 개발 작업·모든 사용자·구독 요금 절감으로 일반화하지 않는다.

현재 드라이런 결과의 120토큰은 테스트 데이터다. 실제 AI 0회와 함께 `synthetic: true`를 표시하며 실제 실험 성능표에 섞지 않는다.
