# 2026-09-09 격리 재감사

**판정: 실제 AI 실험 격리 미통과, PR #38 병합 보류.** 준비 회귀 테스트의 통과와 실제 실험 준비 완료는 다르다. 합성 테스트 수치를 실제 비교 결과로 사용하지 않는다.

## 이전 검증에서 빠진 것

`e8c86a6`에서 임시 파일과 무해한 후보 코드만으로 다음 세 가지를 재현했다. 사용자 비밀값이나 다른 앱의 데이터는 사용하지 않았다.

| 재현 | 영향 | 보완 |
|---|---|---|
| 후보 테스트가 평가 중 옆 디렉터리의 정답 마커를 읽음 | 작성자뿐 아니라 테스트 실행도 상대 정보를 얻을 수 있음 | 평가 전용 읽기 허용 목록, 별도 scratch |
| 후보 테스트가 Judge 클래스를 재컴파일해 덮어씀 | 고장 난 원본도 성공 판정 | 실제 classpath를 읽기 전용으로 분리 |
| 후보 클래스 초기화가 성공 문구를 출력하고 종료 | 검사 전체를 건너뛰고 성공 판정 | Java는 관측값만 출력, 기대값과 최종 판정은 외부 Python에 유지 |

`test_audit.py`의 처음 세 공격 테스트는 수정 전 모두 실패했다. 수정 후 정상 기준 구현 통과와 공격 거부를 함께 검사한다. 컴파일 자체가 깨져 공격이 실패한 것을 보완 성공으로 판단하지 않는다.

## 추가한 방어와 검사

- 평가 프로세스에는 JDK·클래스·필수 시스템 파일과 독립 scratch만 제공한다. 후보가 만든 JVM의 네트워크는 차단한다. 작성자에게 제공하는 공통 네트워크 정책과는 별도다.
- 각 테스트 프로세스의 scratch를 새로 만들며 다른 평가 공간도 읽을 수 없게 한다.
- macOS 평가 프로세스는 기본 거부, 초기 실행 파일만 허용하며 fork·Mach IPC·네트워크를 허용하지 않는다. Linux는 최소 rootfs와 별도 PID·network namespace를 사용한다.
- 작성자가 호스트 조정 프로세스에 신호를 보내는 경로와 macOS Data 볼륨 대체 경로를 검사한다.
- 후보 트리의 특수 파일·하드링크·과도한 디렉터리·깊이·파일 수·바이트 수를 제한한다. 로그 FIFO·하드링크도 집계하지 않는다.
- Git 환경변수·템플릿이 시작 저장소를 바꾸지 않도록 고정한다.
- 평가 전체 120초, JVM heap 256 MiB·metaspace 128 MiB·활성 CPU 2개로 제한한다. 이 값은 작은 벤치마크 전용이며 사용자 전역 Java 설정은 변경하지 않는다.

## 여전히 통과하지 않은 조건

1. **작성자 → 호스트 HTTP 중계 우회가 재현된다.** 직접 읽을 수 없는 마커를 테스트 전용 HTTP 서버가 대신 읽으면, open-network 작성자는 이를 받을 수 있다. `test_evaluated_code_cannot_use_host_http_relay`는 평가기 차단과 작성자 우회가 남았다는 사실을 함께 검사한다. 이 테스트의 통과는 우회 해결을 의미하지 않는다.
2. 호스트 전체를 읽기 전용으로 제공한 뒤 일부 경로를 숨기는 방식은 모든 위치의 비밀값·스킬·훅·설정·Unix 소켓을 격리한 환경이 아니다.
3. 공개 저장소의 기준 구현 재다운로드, 외부 MCP/서비스를 통한 상대 결과 접근을 아직 통제하지 않는다. 인터넷을 몰래 차단해 이 요구를 충족한 것으로 바꾸지 않는다.
4. macOS 작성자 프로세스 그룹은 detached 자식을 완전히 포함하지 못한다. Linux에서도 전체 프로세스·메모리·디스크 자원 한도는 별도 환경 수준의 검증이 필요하다.
5. 실제 Codex·OMX·OML의 설정·인증·전체 세션 계측은 아직 검증하지 않았다.

`readiness.py`는 위 조건을 명시적으로 BLOCKED로 반환하고 `require_live_ready()`는 실제 실행 승인을 거부한다. 실제 AI 실행 CLI 진입점도 없다. 단순히 테스트 수가 늘었다고 true로 바꾸지 않는다.

## 다음 통과 기준

- 동일 사양의 일회용 실행 환경에서 호스트 개인 파일과 IPC를 분리한다.
- 공통 인터넷·도구는 유지하면서 상대 자료/정답에 대한 직접·중계·원격 접근 경계를 정하고 실제 실패를 검증한다.
- 세 실행기의 실제 적용 설정과 자식 세션을 검증한다. 재개·시간 초과 후에도 이전 실행에 접근하지 못해야 한다.
- 메모리·프로세스·디스크 한도를 환경 수준에서 검증한다.

유한한 함수 검사로 모든 악성 JVM 프로그램의 의미적 정확성을 증명하지는 않는다. 이번 수정은 재현한 우회 경로를 닫는 것이며 OS 취약점이나 모든 부채널에 대한 보증이 아니다. [bubblewrap 공식 보안 설명](https://github.com/containers/bubblewrap/blob/main/SECURITY.md)도 실제 경계가 실행 인자와 상위 정책에 달려 있다고 명시한다.
