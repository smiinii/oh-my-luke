# Architecture

## 핵심 구조

```text
CLI
 ↓
Project & Context
 ↓
Preset Selection
 ↓
Graph Kernel
 ├── Runtime Node
 ├── Tool Node
 └── Human Node
 ↓
Policy & Limits
 ↓
State / Events / Artifacts
```

하네스, 루프, 그래프를 별도 엔진으로 구현하지 않는다.

```text
Graph Kernel
├── Direct Preset
├── Loop Preset
└── Workflow Preset
```

## 첫 번째 커널 슬라이스

현재 커널은 AI, 파일, 네트워크 없이 메모리에서 다음 규칙으로 동작한다.

- `Node`는 읽기 전용 `NodeContext`를 받고 `Outcome`과 `StatePatch`를 반환한다.
- 실패 노드는 선택적으로 비밀이 없는 안정적 `FailureInfo`(종류·코드·원인)를 반환하며, 관리 런타임은 이 정보가 있을 때만 동일 실패를 누적한다.
- `Node.fingerprint()`는 노드 종류, 동작 버전, 결과에 영향을 주는 설정을 안정적인 문자열로 제공한다.
- `GraphRunner`만 상태 변경분을 적용한다.
- 모든 실행 노드는 각 `Outcome`에 대해 정확히 하나의 `Condition`이 일치해야 하며, 겹치거나 비어 있는 분기는 실행 전에 거부한다.
- 각 이동은 상태 변경분, 적용 후 상태, 다음 노드와 선택 이유를 `TransitionEvent`로 기록한다.
- 일괄 실행과 저장형 단계 실행은 검증·그래프 인덱스를 한 번 준비해 재사용한다.
- 단계별 불변 이력은 영속 추가 리스트로 연결해 이전 경로와 이벤트 전체를 매번 복사하지 않는다.
- 상태와 이벤트의 맵은 불변이며 입력 및 상태 변경분의 반복 순서를 보존한다.
- 터미널 ID에 도달하면 성공하고, 최대 단계에 도달하면 성공과 구분된 상태로 안전 중단한다.
- 순환이 있는 그래프는 양수인 최대 단계 제한이 없으면 실행 전에 거부한다.

## 상태 저장과 재개 슬라이스

`ManagedRunService`가 순수한 `GraphRunner` 바깥에서 파일 저장과 실행 수명주기를 조정한다. 따라서 그래프 코어에는 파일 시스템이나 CLI 의존성이 들어가지 않는다.

```text
ManagedRunService
├── GraphRunner       한 단계 실행
├── CheckpointStore   state.json 원자적 교체와 백업 복구
├── EventLogStore     events.jsonl 추가 기록
└── HandoffStore      handoff.md 원자적 교체
```

한 노드를 실행하는 순서는 다음과 같다.

```text
READY 체크포인트
  → NODE_STARTED 체크포인트 저장
  → NODE_STARTED 이벤트 기록
  → 노드 실행
  → 정책 카운터·실패·상태 지문 갱신 및 판정
  → 새 READY 체크포인트 저장
  → NODE_COMPLETED 이벤트 기록
  → POLICY_EVALUATED 이벤트 기록
```

- `state.json`은 스키마 버전과 그래프 구조·노드 동작 지문의 SHA-256 서명을 가진다.
- `state.json`에는 실행 시작 시 고정한 정책 설정, 현재 카운터, 반복 실패·무진전 횟수와 마지막 정책 판정도 함께 저장한다.
- 체크포인트 스키마 2는 기존 스키마 1을 제한 비활성화 상태로 안전하게 읽어 올린다.
- 지원하지 않는 스키마는 백업으로 숨기지 않고 명시적으로 거부한다.
- 저장할 때도 현재 구현이 읽을 수 있는 스키마 버전만 허용한다.
- 파일 내부 `runId`와 실행 디렉터리의 ID가 다르면 상태 혼합으로 보고 거부한다.
- 손상된 기본 체크포인트는 마지막 `READY` 백업이 있을 때만 복구한다.
- `NODE_STARTED` 상태는 안전 백업을 덮어쓰지 않는다.
- 이벤트 로그는 UTF-8 문자의 중간을 포함해 완전히 기록되지 않은 마지막 JSONL 줄만 제거하고 복구한다. 정상 접두사는 임시 파일을 거쳐 원자적으로 교체하며, 중간 손상은 오류다.
- 재개할 그래프의 구조 서명이 다르면 노드를 실행하지 않는다.
- 취소 이벤트를 체크포인트보다 먼저 기록하므로 취소 상태 파일이 손상되어도 노드를 다시 실행하지 않는다.
- 체크포인트 저장 뒤 완료 이벤트 기록 전에 종료되면, `inspect`는 체크포인트의 전이 이력으로 완전한 읽기 뷰를 제공하고 다음 변경 작업은 누락 이벤트를 영구 기록한다.
- 실행 ID별 운영체제 파일 잠금으로 두 프로세스가 같은 노드를 동시에 실행하지 못하게 한다.
- 프로젝트 실제 경로를 기준으로 심볼릭 링크 탈출을 검사하고, 임시 파일은 충돌 없는 새 파일로 생성한다.
- 노드 자체의 외부 부작용은 일반적으로 정확히 한 번을 보장할 수 없다. 파일 도구는 작업 ID에 결속된 최초 체크포인트와 완료 상태 검증으로 성공한 변경 재실행을 멱등 처리한다. 프로세스처럼 외부 효과가 있는 도구는 이후에도 멱등성 키나 사전 조건이 필요하다.

현재 독립 실행형 CLI는 저장된 Java 노드 구현을 파일만으로 복원할 수 없다. `inspect`와 `cancel`은 즉시 사용할 수 있고, `resume`은 `GraphResolver`로 실행 가능한 그래프가 등록된 환경에서 사용한다. 프리셋 단계에서 파일 기반 그래프 로딩을 연결한다.

## 정책과 종료 조건 슬라이스

정책 엔진은 그래프 코어 밖에 있으며 AI나 노드의 판단 대신 Java 값만으로 결과를 결정한다.

- `SUCCESS`: 전달된 완료 사실이 `all` 또는 `any` 조건을 객관적으로 만족함
- `LIMIT_REACHED`: 반복, 경과 시간, 노드·도구 호출 또는 사용량 한도 도달
- `BLOCKED`: 같은 실패 반복, 무진전, 프로젝트 경계 또는 권한 정책 위반
- `CANCELLED`: 사용자 취소
- `CONTINUE`: 위 조건에 해당하지 않아 실행 가능

완료 조건은 실제 명령을 실행하지 않고 종료 코드, 파일 존재, 중대 오류 개수, 요구사항 충족 여부로만 판정한다. 도구 권한은 명령 문자열이 아니라 `ALLOW`, `ASK`, `DENY` 능력과 정확한 대상을 사용한다. 이번만·현재 실행·현재 프로젝트 승인은 실제 프로젝트 루트, 능력, 대상, 만료 시각에 결속된다. 프로세스 대상과 노드 지문은 모호한 `toString()` 연결이 아니라 길이 접두어 직렬화로 만든다. 프로젝트 자율 실행은 결속된 프로젝트의 `ASK`만 자동 허용하며 OML 정책 변경, 샌드박스 우회, 비밀정보 노출, 보호 데이터 훼손은 항상 `DENY`다.

`ManagedRunService`는 노드마다 반복·노드 호출 수와 상태 지문을 갱신하고 설정된 제한에 도달하면 다음 노드를 실행하지 않는다. 시간 제한은 재개 직전에도 다시 검사한다. `inspect`는 마지막 정책 결과·이유·재개 가능 여부와 모든 카운터를 표시한다.

## 범용 도구 노드 슬라이스

```text
FileToolNode / ProcessToolNode
  → ToolPermissionEvaluator
      ├── DENY 불변식
      ├── 기본 ALLOW
      ├── 저장된 ONCE / RUN / PROJECT 승인
      └── 프로젝트 자율 실행
  → 구조화 도구 실행
  → 아티팩트 저장
  → ExecutionMetrics(toolCalls, usage)
  → 그래프 전이와 정책 카운터
```

- `ProjectPermissionManager`는 `.oml/permissions.json`을 원자적으로 저장하며 일회 승인을 소비한 결과도 즉시 반영한다.
- `FileTool`은 파일 변경 전 복구 체크포인트를 만들고 `.oml`, 비밀 파일, `.git` 직접 변경, 심볼릭 링크 접근을 차단한다.
- `ProcessTool`은 원본 프로젝트 대신 민감 경로를 제외한 임시 사본을 사용한다.
- macOS Seatbelt와 Linux bubblewrap이 파일·네트워크 경계를 강제한다. 사용할 수 없으면 실행하지 않는다.
- 파일 체크포인트는 최초 스냅샷 불변성, HMAC 무결성, 전체 manifest 선검증, POSIX·DOS 메타데이터 복구를 보장한다.
- 같은 프로젝트의 파일 변경·복구 전체 구간은 JVM·운영체제 잠금으로 직렬화하며, 성공 후 재시도는 현재 파일 상태를 체크포인트의 기대 결과와 비교해 실행 없이 이전 성공을 재사용한다.
- 파일 내용과 프로세스 출력은 그래프 상태가 아니라 `.oml/runs/<run-id>/artifacts/`에 저장한다. 상태에는 경로, 종료 코드, 권한 이유와 크기만 기록한다.
- 도구 노드는 성공, 승인 필요, 영구 차단, 비정상 종료, 시간 초과를 안정적인 `FailureInfo`로 구별하고 호출 수를 `ExecutionMetrics`로 보고한다.

## 로컬 프로젝트 스캐너 슬라이스

`ProjectScanner`는 AI나 네트워크, 빌드 도구를 실행하지 않고 프로젝트의 결정적인 메타데이터 지도인 `ProjectProfile`을 만든다.

```text
프로젝트 실제 경로 확인
  → 이름순 제한 탐색
  → 민감·내부·생성·바이너리 경로 제외
  → 빌드 시스템·언어·소스/테스트 루트 탐지
  → 구조화된 빌드/테스트 명령 후보 생성
  → 한도와 제외 사유를 포함한 불변 프로필 반환
```

- 탐색 순서는 운영체제의 디렉터리 순서에 의존하지 않고 정규화한 상대 경로순으로 고정한다.
- 한 디렉터리의 항목 수가 남은 항목 한도보다 많으면 운영체제 나열 순서에 따른 부분 결과를 쓰지 않고 해당 지점에서 잘림 처리한다.
- `.git`, `.oml`, 생성 디렉터리와 공통 민감 경로는 내려가지 않으며 심볼릭 링크는 대상이 프로젝트 안이어도 따라가지 않는다.
- 항목 수, 포함 파일 크기 합계, 탐색 깊이 한도로 탐색이 잘리면 `truncated`와 구체적인 사유를 표시한다. 개별 크기 한도 초과 파일은 `LARGE_FILE_SKIPPED` 사유로 제외한다.
- 파일 본문은 프로필에 포함하지 않는다. `package.json`도 제한된 크기 안에서 `build`와 `test` 스크립트의 존재만 읽으며 스크립트 값은 버린다.
- 프로젝트 루트의 Gradle, Maven, npm 표식만 루트 실행 명령 후보를 만든다. 명령은 문자열 셸 명령이 아니라 인자 목록일 뿐이며, 스캐너가 실행하거나 승인하지 않고 이후 도구·권한 계층이 별도로 판정한다.

## 가짜 AI 실행기 슬라이스

AI 제공자와 그래프 사이에는 `AiRuntime` 계약을 둔다. `FakeAiRuntime`은 이 계약의 첫 구현이며 외부 시스템을 호출하지 않고 정확한 요청·결과 스크립트를 메모리에서 재생한다.

```text
AiNode
  → 설정된 상태 키만 AiRequest로 구성
  → AiRuntime.invoke
      └── FakeAiRuntime: 논리 호출 ID의 예상 요청과 정확히 비교
  → 성공: 출력 상태 반영 + usage 보고
  → 실패: 안정적인 FailureInfo + usage 보고
  → ManagedRunService가 정책 카운터와 한도에 반영
```

- 요청은 run ID·노드 ID·실행 단계로 해시한 호출 ID, 지시문, 명시적으로 선택한 문맥으로 구성되며 문맥 키를 정렬한 불변 값이다.
- AI 노드는 명시적인 run ID가 없는 그래프 기본 실행 범위에서는 런타임을 호출하지 않고 실패한다. 관리 실행은 체크포인트의 run ID를 자동 전달한다.
- 가짜 스크립트는 논리 호출 ID로 결과를 찾는다. 같은 호출의 재시도는 같은 결과를 재생하며, 요청 내용 불일치와 등록되지 않은 호출은 서로 다른 실패 코드다.
- 노드와 가짜 실행기의 지문은 길이 접두어 직렬화와 SHA-256을 사용해 설정, 논리 요청 집합, 결과와 사용량 차이를 구분한다.
- AI 호출은 도구 호출로 세지 않고 `usage`만 별도로 보고한다. 노드 호출 수는 기존 그래프 정책이 계산한다.
- `usage`는 호출 결과를 받은 뒤 누적된다. 한 호출의 사용량을 미리 알 수 없으므로 남은 한도를 넘는 호출 자체를 사전 차단하지는 못하고 이후 노드부터 중단한다.
- 실행기 실패는 `AiFailureCode`에 등록된 코드와 공개 메시지만 영속화한다. 제공자의 stderr·예외 원문이나 임의 문자열은 상태나 이벤트에 넣을 수 없다.
- 실제 인증 중계와 외부 AI 호출의 멱등 결과 저장은 다음 `CodexCliRuntime`에서 별도 설계한다.

## 초기 패키지 방향

```text
io.ohmyluke
├── cli
├── graph
├── state
├── policy
├── budget
├── project
├── context
├── tool
├── validator
├── runtime
├── node
└── preset
```

빈 패키지를 미리 만들지 않는다. 각 단계에서 실제 책임이 생길 때 추가한다.
