# Experiment

## 목적

Codex 직접 실행과 OML 실행을 같은 조건에서 비교해 OML이 검증 성공률을 유지하거나 높이면서 기록 토큰과 AI 호출을 줄이는지 확인한다.

## 실험 모드

Open-world isolated-arms benchmark를 사용한다.

- 양쪽 모두 같은 인터넷, 웹 검색, 문서, MCP, 도구를 사용할 수 있다.
- 양쪽은 같은 시작 코드, 모델, reasoning, 제한 시간을 사용한다.
- Baseline은 OML의 파일, 상태, 세션, 결과를 읽지 못한다.
- OML은 Baseline의 파일, 상태, 세션, 결과를 읽지 못한다.
- Judge만 양쪽 결과를 읽고 동일한 완료 조건으로 판정한다.
- 인증 정보와 비밀 파일은 양쪽 모두 읽지 못한다.

## 주요 지표

- 검증 성공률
- 입력, 출력, 캐시, 전체 기록 토큰
- AI 실행 횟수
- 완료 시간
- 동일 실패 반복률
- 체크포인트 복구 성공률

Codex 비대화형 실행의 주 측정값은 `codex exec --json`이 내보내는 `turn.completed.usage`에서 수집한다. 입력, 캐시 입력, 출력, 추론 출력 토큰을 분리하고 전체 기록 토큰은 입력과 출력만 더해 하위 항목을 중복 계산하지 않는다. 필드가 없거나 로그 스키마를 알 수 없으면 추정하지 않고 지원하지 않는 형식으로 처리한다.

로컬 세션의 `token_count` 이벤트 수집기는 향후 대화형 기준선이나 교차 검증이 필요할 때 추가한다. OML 어댑터는 `--ephemeral` JSONL에서 직접 측정하므로 세션 파일 추측에 의존하지 않는다. 최종 비교에서 Baseline과 OML은 같은 Codex 실행 방식, 모델과 reasoning 설정을 사용해야 한다.

## 결과 공개 원칙

- 성공과 실패 결과를 모두 보존한다.
- 개발 과제와 최종 검증 과제를 분리한다.
- 한 번의 실행으로 효과를 단정하지 않는다.
- 실제 측정하지 않은 비용 절감을 주장하지 않는다.
- 원시 JSON 결과와 집계 방법을 함께 공개한다.
