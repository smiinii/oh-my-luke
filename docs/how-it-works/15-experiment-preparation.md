# 15. 비교 실험을 믿을 수 있도록 준비하기

같은 문제를 Codex·OMX·OML에 주고 성공률과 토큰을 비교하기 위한 **준비 단계**다. 현재 실행자는 가짜 작성자이며 실제 AI 호출·토큰 절감 증거는 없다. 인터넷을 사용하는 실제 비교는 아직 `BLOCKED`다.

## 무엇을 비교하나

배송비 버그 수정(A), 할인 기능 추가(B), 중복 검증 리팩터링(C)과 별도 연습 과제를 만들었다. 세 비교군에 시작 코드·완료 조건·공통 문서를 동일하게 제공한다. 현재 공개된 정답은 개발 검사용이며, 본 실험에는 별도로 동결한 비공개 과제가 필요하다.

## 어떻게 분리했나

1. 조정자가 같은 시작 파일을 복사하고 해시와 Git 커밋을 고정한다.
2. 각 실행마다 새 Linux 컨테이너와 전용 메모리 디스크를 만든다. 호스트 폴더나 Docker 소켓은 연결하지 않는다.
3. 작업자는 자기 프로젝트를 읽고 수정한다. HOME·임시 파일·캐시도 실행마다 새로 만든다.
4. 작업이 끝나면 **자식까지 포함해 컨테이너 전체를 일시정지**한다. 별도의 읽기 전용 회수기가 수정 파일만 가져온다.
5. 컨테이너와 전용 디스크를 제거하고, 별도 OS 샌드박스의 평가기가 후보 코드를 검사한다.
6. 성공·실패·시간 초과와 계측 결과를 저장해 비교표를 재생성한다.

따라서 작성자가 채점 중에도 파일을 바꾸거나, detached 자식을 남겨 다음 실행에 영향을 주는 경로를 줄인다. Docker·Python은 **실험 개발 도구**이며 OML 사용자 설치 요건이 아니다.

## 무엇을 허용하고 차단하나

아래는 `--container-image`로 선택하는 **오프라인 준비 환경** 기준이다. 기존 로컬 회귀 경로를 같은 수준의 격리로 취급하지 않는다.

| 대상 | 처리 | 검증 방식 |
|---|---|---|
| 자기 프로젝트·공통 규칙 | 읽기·수정 허용 | 같은 시작 커밋 확인, 정상 수정 평가 |
| Java 컴파일·실행·자식 프로세스 | 자원 한도 안에서 허용 | 실제 javac/java 실행 |
| 상대 코드·정답·로그·이전 HOME | 환경에 제공하지 않음 | 호스트 마커·이전 실행 마커 접근 검사 |
| 호스트 개인 폴더·인증·Docker 소켓 | 마운트·환경변수 전달 안 함 | 경로·환경 검사, 프록시 상속 제거 |
| 호스트 HTTP 중계 | 차단 | 실제 마커 서버는 호스트에서 응답, 작업자에서는 접근 실패 |
| 외부 인터넷·IPv4·IPv6·MCP | 준비 환경에서는 전부 차단 | 연결 실패 검사; 실제 비교의 허용 정책과 구분 |
| 컨테이너 시스템 파일·권한 상승 | 읽기 전용·비특권 | 쓰기 실패, UID·capability·no-new-privileges 검사 |
| CPU·메모리·프로세스·디스크 | 2 CPU, 1 GiB, 64 PID, 작업 256 MiB·임시 64 MiB | cgroup 설정과 자원 초과 공격 검사 |
| 무한 실행·출력 폭주 | 시간·출력 제한 후 제거 | 시간 초과·출력 초과·자식 정리 검사 |
| 파일 회수 우회 | 링크·특수 파일·상위 경로·중복 경로 거부 | 악성 tar와 실제 심볼릭 링크 검사 |
| 채점 기준·평가기 클래스 변경 | 작업자에게 미제공, 후보 JVM에서는 읽기 전용 | Judge 덮어쓰기·성공 문구 위조 공격 거부 |

후보가 추가한 테스트도 신뢰하지 않는다. 원본 테스트·빌드 파일 변경을 거부하고, 회귀 테스트가 원래 버그를 실제로 잡는지 검사한다. JVM이 출력한 “성공” 대신 외부 조정자가 관측값을 기대값과 비교한다.

## 신빙성을 어디까지 말할 수 있나

**재현한 우회 차단과 정상 작업 통과는 확인하지만, “오차 0”이나 “완전한 격리”를 보증하지 않는다.** 테스트 개수는 안전 확률이 아니다. 확인하지 않은 경로와 건너뛴 테스트는 별도로 표시한다.

- 기존 평가기 우회 3가지는 수정 전 재현하고 수정 후 거부했다.
- 컨테이너 검사는 정상 Java 작업과 파일·네트워크·권한·자원·수명 공격을 함께 실행한다. Docker가 없다고 일반 프로세스로 우회하지 않는다.
- 조정자 강제 종료·호스트 장애 뒤 자동 청소는 미검증이다. 정상 관리 중에도 제거에 실패하면 기록을 남기고 다음 실행을 중단한다.
- A 과제의 세 가짜 비교군이 같은 시작 커밋으로 실행·외부 평가·보고서 생성까지 통과했다. 토큰 120 등의 값은 **SYNTHETIC 샘플**이다.
- Linux 배포 압축파일 불일치도 재현했다. `lib/modules` 내부 JLI 클래스 사전 생성을 제외한 뒤 연속 3개 SHA-256이 일치했다. CI는 실패해도 원본 압축파일과 차이 보고서를 보존한다.
- 인터넷 허용 시 호스트·상대 결과·공개 정답 접근을 막는 정책, 실제 인증·OMX 하위 세션 계측, 제품 선행 기능 [#37](https://github.com/smiinii/oh-my-luke/issues/37)은 미완료다. 그래서 실제 실험과 병합을 보류한다.

## 어떤 기록을 남기나

- `manifest.json`: 과제·실행 순서·시작 커밋·도구 해시·이미지 ID·네트워크/자원 정책.
- `execution.json`: 종료 코드·시간·출력·일시정지/제거 확인·작업자 시작 커밋.
- `stdout.jsonl`, `stderr.txt`, `usage-manifest.json`: 원시 사건과 로그 해시·세션 목록. 부모·자식 중복 집계를 막고 누락을 0으로 바꾸지 않는다.
- `result.json`, `results.json`: 실패·시간 초과까지 포함한 전체 판정. 기존 출력 경로를 덮어쓰지 않는다.
- `summary.csv`, `report.md`: 같은 기록에서 다시 만들 수 있는 비교표. 입력+출력을 총토큰으로 삼고 캐시·추론 부분량을 다시 더하지 않는다.

지금 로그에는 실제 인증정보가 없다. 실제 로그는 비공개 보관·비밀값 제거 후 공유해야 하며, 본 실험 결과는 아직 작성하지 않았다.
