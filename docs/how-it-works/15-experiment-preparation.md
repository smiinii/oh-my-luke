# 15. 실제 AI 없이 비교 실험 준비하기

OML이 토큰을 줄이는지 확인하기 전에, 문제·정답 검사·측정 도구가 올바른지 먼저 검증하는 단계다. 실제 Codex·OMX·OML 비교 결과는 아직 없다.

## 이번에 만든 것

- 배송비 버그, 할인 추가, 검증 중복 제거와 별도 연습 과제의 작은 Java 프로젝트.
- 시작 코드와 기준 구현, 같은 성공 조건을 적용하는 평가기.
- 상대 실행 결과를 못 읽게 하는 로컬 OS 격리와 시간·출력 제한.
- 부모와 하위 에이전트 사용량을 중복 없이 집계하는 샘플 계측기.
- 모든 실행 기록으로 비교표를 재생성하는 Python 개발 도구. 배포되는 OML의 Java 본체에는 포함하지 않는다.

## 동작 순서

같은 시작 코드를 독립 디렉터리에 복사 → 가짜 작성자가 수정 → 별도 평가기가 검사 → 가짜 토큰과 결과 저장 → 비교표 생성.

가짜 실행은 실제 AI 0회다. 보고서의 SYNTHETIC 표시는 수치가 테스트 데이터라는 뜻이다.

## 왜 검사를 따로 하나

테스트를 지우거나 빈 회귀 테스트를 추가해서 통과한 것처럼 보이면 비교가 틀어진다. 원본 테스트 변경을 막고, 추가 테스트가 실제 버그를 잡는지도 확인한다. 리팩터링은 실행 결과뿐 아니라 실제 클래스의 공통 검증기 호출도 확인한다.

## 증거와 한계

2026-09-09 재검사에서 평가기 우회 세 가지를 재현해 보완했다. 후보 JVM의 출력 중 성공 문구를 믿지 않고 외부에서 관측값을 비교하며, 평가 파일을 읽기 전용으로 분리했다. **작성자의 호스트 HTTP 중계 경로는 여전히 열려 있어 격리 전체는 미통과다.** [감사 보고서](../../experiments/01-token/audit.md)에 수정 사항과 남은 조건을 기록했다.

`experiments/01-token/tests`와 `Experiment preparation (no AI)` CI에서 과제·격리·계측·결과 재생성을 검증한다. macOS와 Linux를 각각 검사한다.

현재 제품에는 신규 파일 생성과 macOS Gradle 검증 제약이 있다. [#37](https://github.com/smiinii/oh-my-luke/issues/37)로 분리했으며, 준비 도구가 통과해도 아직 실제 비교를 시작할 수 있다는 뜻은 아니다. 인증·OMX 실제 로그·원격 자료 재접근은 후속 검증이 필요하다.
