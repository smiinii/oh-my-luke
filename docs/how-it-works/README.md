# OML은 지금 어떻게 작동하는가

이 폴더는 코드를 읽지 않아도 OML의 현재 동작을 이해할 수 있도록 설명한다. 한 파일이 너무 길어지지 않도록 마일스톤마다 별도 문서로 관리한다.

## 전체 그림

OML은 AI 모델 자체가 아니다. 사용자의 목표를 작은 단계로 실행하고, 결과를 검사하고, 필요한 경우 반복하며, 상태와 권한을 안전하게 관리하는 로컬 실행기다.

```text
사용자 목표
→ 그래프가 다음 작업 선택
→ 노드 실행
→ 결과와 진행 상태 기록
→ 완료·계속·중단 판단
→ 다음 노드 또는 종료
```

하네스, 루프, 그래프를 각각 따로 만들지 않는다. 하나의 그래프 커널 위에 Direct, Loop, Workflow 프리셋을 올리는 구조다.

현재는 Direct·Loop 파일 수정 흐름과, 검사·수정·승인을 순차 연결하는 정적 Workflow까지 구현한 단계다. 그래프 실행, 중단·재개, 완료 조건, 권한, 파일·프로세스 도구, 프로젝트 스캔과 Codex CLI 호출을 연결했다. 범용 개발 작업 전체가 완성된 단계는 아니다.

## 지금 가능한 것

- 결정적인 그래프 실행과 순환 제한
- 상태·이벤트·인수인계 저장
- 중단 검사, 취소, 등록된 그래프 재개
- 객관적 완료와 안전 중단 판정
- 기억되는 권한과 프로젝트 자율 실행
- 복구 가능한 구조화 파일 작업
- macOS/Linux의 격리된 구조화 프로세스 실행
- 프로젝트 구조·언어·빌드 시스템의 결정적인 로컬 탐지
- 안전 한도를 적용한 빌드·테스트 명령 후보 생성
- 토큰과 네트워크 없이 AI 성공·실패·사용량 흐름 재현
- 사용자가 저장한 Codex CLI 로그인 상태 확인과 실제 비대화형 호출
- Codex 기본 모델 상속 또는 실행별 모델·추론 강도 재정의
- JSONL 최종 응답·세션 ID·토큰 사용량 파싱과 호출 결과 재사용
- 작업표 기반 `run`, 모델 선택, 작은 파일 수정·검증, 제한된 재시도와 독립 CLI 재개
- 정적 `workflow` 선언, AI 없는 선검사, 순차 분기·합류, 사람 승인 결정과 재개

## 다른 문서와 증거

- 이 폴더: 코드 없이 현재 동작 이해
- `product.md`: 제품 범위와 하지 않기로 한 것
- `architecture.md`: 개발자가 보는 상세 구조
- `security.md`: 권한과 보안 경계
- `runtime-auth.md`: 사용자의 AI CLI를 연결하는 방식
- `experiment.md`: 토큰 절감과 성공률을 증명하는 방법
- `adr/`: 중요한 결정을 내린 이유
- 테스트와 CI: 문서에 적힌 동작이 실제로 반복 검증됐다는 증거
- PR 리뷰: 문제를 발견하고 수정한 과정의 증거

문서는 주장과 설계 근거를 남긴다. 실제 동작의 증거는 자동화 테스트, 운영체제별 CI, 재현 가능한 실험 결과가 함께 제공해야 한다.
