# 18. 질문별 사용량을 확인하는 방법

## 무엇을 만들었나

`omluke usage`로 **이 프로젝트에 제출한 작업 하나당 얼마나 기록됐는지** 본다. 한 질문에 재시도가 두 번 있었다면 한 행 안에 두 시도를 묶는다. 상세 조회와 JSON·CSV 내보내기도 같은 계산 결과를 사용한다. [사용법과 측정 계약](../usage-records.md)에 예시가 있다.

## 어떻게 계산하나

작업표와 실행 이력 → 호출 ID 복원 → 기존 Codex 저장 결과 조회 → 단계별 사용량 대조 → 질문별 합계 순서다. 새로운 누계 파일을 계속 더하는 방식이 아니므로 같은 질문을 다시 조회하거나 재개했다고 토큰을 한 번 더 더하지 않는다. 캐시·추론 항목도 합계에 이중으로 더하지 않는다.

`완료`는 AI 응답 성공, `통과`는 작업 검증 성공이다. AI가 답했다고 검증이 통과한 것으로 표시하지 않는다.

## 이상한 숫자를 어떻게 막나

- 누락은 0이 아니라 `확인 불가`. 일부만 확인되면 부분합이라고 표시한다.
- 저장 결과와 실행 단계 숫자가 다르면 해당 사용량을 확정하지 않는다.
- 동일 세션 중복, 중단 후 재실행, 잘린 로그·백업 복구도 경고한다.
- 실행 중에는 잠금으로 조회를 거부하고, 다른 프로젝트로 향하는 링크는 읽지 않는다.
- 토큰 합계는 큰 정수로 계산하며 JSON은 문자열로 내보내 숫자 반올림을 피한다.
- 원본 계정 인증 정보나 저장된 AI 답변을 조회 화면으로 내보내지 않는다.

## 검증 근거와 한계

`UsageReportTest`는 재시도·재개·Workflow의 두 EDIT·미기록·0·큰 정수·백업·로그 누락·동시 실행·프로젝트 경계와 실제 가짜 CLI 저장 결과를 확인한다. `CodexUsageReaderTest`는 저장 응답/토큰 및 중복·누락·오버플로를, `UsageCliTest`는 화면/JSON/CSV 숫자와 비변경성을 대조한다. 패키지에서도 외부 Java 없이 빈 기록 조회가 실행되는지 확인한다. 최종 테스트 수·CI 결과는 PR에 남긴다.

**이력과 기록이 맞는다는 것과 실제 총 소비량을 모두 아는 것은 다르다.** CLI 내부 자식 에이전트·포크의 포함 관계나 결과 저장 전 강제 종료로 잃은 소비량은 완전하게 알 수 없다. 구독 차감률·계정 전체 한도 화면도 이번 범위가 아니다. 다른 하네스 전환은 이 단계 다음에 이어간다.
