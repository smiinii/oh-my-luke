# 11. Java를 포함한 개발 패키지

## 무엇을 만들었는가

운영체제에 맞는 OML 실행 파일, 애플리케이션, 필요한 Java 21 런타임을 하나의 앱 이미지로 묶고 `tar.gz`로 압축한다. 사용자는 이 압축본을 실행할 때 OML용 Java를 따로 설치하지 않아도 된다.

공개 설치 프로그램을 만든 단계는 아니다. macOS와 Linux의 패키징·실행·크기 검증 기반을 먼저 만든 것이다.

## 내부 처리 순서

```text
OML과 의존성 빌드
→ 필요한 Java 모듈만 넣은 운영체제별 앱 이미지 생성
→ 실행 권한과 심볼릭 링크를 보존해 tar.gz 압축
→ 새 임시 폴더에 압축 해제
→ 외부 Java가 없는 환경에서 실행
→ AI 없는 승인·재개·검사 성공 확인
→ 크기와 SHA-256 기록
```

macOS와 Linux 앱 이미지는 구조와 실행 파일 위치가 다르므로 각 운영체제의 CI가 자기 패키지를 직접 만든다. 다른 운영체제용 파일을 교차 생성하지 않는다.

## 왜 필요한가

Java는 OML의 개발 언어일 뿐, 사용자에게 JDK 설치 작업을 떠넘길 이유는 없다. 자체 포함 패키지는 실행 환경 차이를 줄이고 이후 GitHub Releases·Homebrew·WinGet이 같은 검증된 파일을 전달하게 만드는 기반이다.

원본 앱 이미지가 아니라 압축 해제본을 검사하므로, 실제 전달 과정에서 실행 권한이 빠진 문제도 출시 전에 발견할 수 있다.

## 검증 근거

`PackagedApplicationTest`는 빈 `PATH`와 격리된 홈에서 다음을 확인한다.

- 포함된 Java와 OML 런처가 실행 가능하고 런타임 링크가 보존됨
- `jpackage` 버전 메타데이터와 macOS 번들 무결성이 유지됨
- 도움말이 정상 출력됨
- AI 호출 없이 승인 대기 후 별도 프로세스에서 승인·재개함
- 최종 결과가 성공이고 AI 시도·사용량이 0임
- 압축 50MB, 앱 이미지 150MB 초기 기준을 넘지 않음
- 운영체제·CPU·Java 버전·크기·SHA-256을 JSON으로 남김

macOS·Ubuntu CI가 같은 검증을 반복하고 개발 패키지와 근거 JSON을 임시 artifact로 보관한다. 자세한 재현 명령과 범위는 [자체 포함 개발 패키지](../distribution.md)에 있다.

## 아직 하지 않는 것

- 공개 GitHub Release와 장기 배포
- 서명·공증과 운영체제 설치 프로그램
- Homebrew·WinGet과 자동 업데이트
- Windows 패키지
- 패키지가 만들어진 운영체제의 모든 OML 기능 지원 선언

Codex를 실제로 쓰는 작업은 여전히 Codex CLI 설치와 사용자 로그인이 필요하다. 패키지에 포함된 Java와 사용자의 AI 구독은 서로 다른 문제다.
