# 17. 실행기와 모델을 선택하는 터미널 화면

## 무엇을 만들었나

`setup`과 `switch`에서 **실행기 → 하네스 → 모델 → 적용 범위 → 저장 확인**으로 이어지는 같은 선택 화면을 만들었다. 공개 RC에는 아직 없으며 현재 실제 선택·연결은 Codex + OML이다. 사용법은 [실행 설정](../execution-settings.md)에 있다.

처음에는 사용자 기본값으로 저장하고 프로젝트 범위를 따로 묻지 않는다. 이후 프로젝트에서 전환하면 이 폴더만 고정하거나 사용자 기본값을 따르게 할 수 있다. 기존 실행은 중간에 모델을 바꾸지 않는다.

## 설치된 것과 연결 가능한 것은 다르다

`runtimes`는 PATH에서 알려진 CLI 파일만 찾고 실행하지 않는다. Codex·Claude Code·OpenCode와 OMX·OMC·OMO를 구분하지만 모든 앱이나 플러그인을 자동 발견하는 기능은 아니다.

다른 실행기나 하네스가 보여도 어댑터가 없는 조합은 준비 중으로 표시하고 선택하지 못하게 한다. 특히 OMX가 발견됐다고 OML과 함께 실행하거나 OMX 전역 설정을 지우지 않는다. 하네스 간 전환·외부 후크 격리는 별도 검증이 필요하다.

## 모델은 어디서 가져오나

사용자가 Codex를 고른 뒤 공식 CLI에 **메타데이터만** 요청한다. 계정 로그인 상태를 확인하고 실제 반환된 모델 목록을 페이지별로 읽는다. OML이 요금제 이름으로 모델을 추측하지 않는다.

목록을 읽지 못하면 이유를 안내하고 기존 선택 또는 “실행기 설정 그대로 사용”만 남긴다. 조회 성공도 모든 모델의 사용 권한이나 잔여 한도를 보증하지는 않는다. “CLI 권장”과 “사용자가 선택한 모델”도 구분한다.

## 잘못 저장되는 상황을 어떻게 줄이나

- 마지막 저장 확인 전에는 설정을 쓰지 않는다.
- `b`로 이전 단계, `0`/`q`/EOF로 취소한다. 목록은 8개씩 나누며 `n`/`p`로 이동한다.
- 빈 입력을 동의로 해석하지 않는다. 잘못된 입력 3회에는 멈춘다.
- 화면을 띄운 동안 다른 곳에서 같은 범위의 설정을 바꾸면 덮어쓰지 않고 재확인을 요청한다.
- 비대화형 실행은 기존 명시 옵션을 사용한다. 파이프 입력을 메뉴 승인으로 읽지 않는다.

## 검증 근거

- `RuntimeDiscoveryTest`: 명령 파일을 실행하지 않는 탐지, 미감지, 잘못된 PATH·프로젝트 내부 실행 파일 차단.
- `CodexModelCatalogTest`: 계정 상태 구분, 실제 모델 ID, 숨김 모델 제외, 페이지·중복·필드 검증, 계정 식별자 미노출.
- `CodexCatalogClientTest`: 실제 별도 JVM의 JSONL 교환, 지연·폭주·잘못된 ID·계정 변경·서버 요청 거부, 종료·관찰된 자식 정리, 프로세스 조회 불가 처리.
- `RuntimePickerTest`: 저장 전 취소/EOF, 뒤로가기·페이지 이동, 전역/프로젝트 선택, 동시 변경 보호.
- `StartCliTest`: 화면에서 저장한 모델이 기존 실행 경로를 거쳐 가짜 AI에 실제로 전달되는지 확인.
- 실제 터미널 QA: 임시 HOME과 가짜 Codex로 조회 실패 후 취소, 정상 모델 조회·뒤로가기·저장, 프로젝트 범위 전환 확인. 개발 중 재생성되는 파일과 섞이지 않도록 고정된 실행 파일로 재확인한다.
- 실제 설치된 Codex CLI에서도 메타데이터 목록 조회를 확인했다. 답변 생성 요청은 하지 않았다. 전체 테스트·패키지의 최종 결과는 PR에 기록한다.
