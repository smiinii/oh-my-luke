# 마일스톤 7: Codex CLI 실행기와 모델 선택

## 무엇을 만들었나

사용자가 이미 설치하고 로그인한 공식 Codex CLI를 OML의 첫 실제 AI 실행기로 연결했다. OML이 API 키를 받거나 별도 모델 비용을 대신 내는 구조가 아니다.

```text
OML의 AI 노드
→ CodexCliRuntime
→ 사용자 컴퓨터의 codex exec
→ 사용자가 로그인한 ChatGPT 계정
```

모델과 추론 강도를 지정하지 않으면 사용자의 Codex 설정을 그대로 상속한다. 실행 설정에서 명시한 경우에만 `--model`과 `model_reasoning_effort`를 이번 호출에 전달한다. OML이 모델 이름 목록을 고정하지 않으므로 새 모델이 추가될 때마다 OML을 업데이트할 필요는 없고, 사용할 수 없는 모델은 공식 CLI가 오류로 판정한다.

## 어떤 순서로 처리하나

```text
설치·로그인 확인
→ 논리 호출 ID의 저장 결과 확인
→ 민감 파일을 제외한 임시 프로젝트 사본 생성
→ 선택한 상태와 지시문을 JSON으로 표준입력 전달
→ codex exec --json을 읽기 전용으로 실행
→ 최종 응답·세션 ID·토큰 사용량 파싱
→ 결과를 원자적으로 저장
→ AI 노드와 정책에 결과·전체 기록 토큰 전달
```

설치 여부는 `codex --version`, 로그인 여부는 `codex login status`의 성공 여부로 확인한다. OML은 `~/.codex/auth.json`이나 운영체제 자격 증명 저장소를 직접 열지 않는다. 자식 프로세스에는 일반 경로와 저장된 로그인에 필요한 환경만 남기고 API 키·토큰·비밀번호 형태의 환경 변수는 제거한다.

Codex가 보는 작업공간은 원본이 아니다. `.git`, `.oml`, `.env`, 인증 설정, 키·인증서와 빌드 산출물을 제외한 일회용 복사본이며 이번 단계는 `read-only`로만 실행한다. 복사본에 `.git`이 없으므로 OML이 이미 격리한 경계 안에서 `--skip-git-repo-check`를 사용한다.

## 모델 선택은 어떻게 동작하나

현재 Java 설정의 우선순위는 다음과 같다.

```text
명시한 실행별 모델·추론 강도
→ 없으면 사용자의 Codex 설정 상속
```

예를 들어 모델만 지정하고 추론 강도를 생략하면 모델만 재정의하고 추론 강도는 사용자 설정을 따른다. 사용자용 `omluke run --model ...` 명령은 Direct·Loop 프리셋과 함께 다음 단계에서 이 설정에 연결한다.

## 토큰과 재실행은 어떻게 다루나

`codex exec --json`의 `turn.completed.usage`에서 다음 값을 읽는다.

- 입력 토큰
- 캐시된 입력 토큰
- 출력 토큰
- 추론 출력 토큰

정책 한도에 전달하는 전체 기록 토큰은 `입력 + 출력`이다. 캐시 입력은 입력의 일부이고 추론 출력은 출력의 일부이므로 다시 더하지 않는다. 필드가 없거나 형식이 다르면 추정하지 않고 사용량 미지원으로 남긴다.

완료된 논리 호출은 요청·실행기 설정의 지문과 함께 `.oml/runtime/codex/invocations/`에 저장한다. 같은 호출을 다시 실행하면 모델을 부르지 않고 저장 결과를 반환한다. 같은 호출 ID에 다른 요청이나 모델 설정이 들어오면 실행 전에 거부한다. JVM과 운영체제 파일 잠금을 함께 사용해 두 프로세스가 같은 호출을 동시에 시작하지 못하게 한다.

## 검증 근거

- 가짜 Codex 실행 파일로 기본 설정 상속, 모델·추론 재정의와 인자 분리를 검증한다.
- 정상 JSONL, 세션 ID, 토큰 세부 항목과 전체 기록 토큰 계산을 검증한다.
- 인증 필요, 비정상 종료, 시간 초과, 잘못된 JSONL, 입력·출력 한도 초과를 안전한 실패 코드로 검증한다.
- 같은 호출의 순차·동시 재시도가 실제 실행을 한 번만 하는지 검증한다.
- 기본 CI는 구독을 사용하지 않는다. `OML_CODEX_INTEGRATION=true`일 때만 사용자의 실제 저장 로그인으로 스모크 테스트를 실행한다.
- 개발 환경의 `codex-cli 0.149.1`과 ChatGPT 저장 로그인으로 실제 스모크 테스트를 통과했다.

## 현재 한계

- 사용자용 `omluke run` 명령과 Direct·Loop 프리셋은 아직 없다.
- Codex가 만든 파일 변경을 원본 프로젝트에 반영하지 않는다. 이번 어댑터는 읽기 전용 응답 생성만 담당한다.
- 저장된 ChatGPT/공식 CLI 로그인 재사용만 다룬다. API 키·기업 자동화용 환경 토큰은 이번 범위에서 전달하지 않는다.
- 모델 이름의 실제 사용 가능 여부는 계정·워크스페이스와 CLI 버전에 따라 달라지므로 OML이 미리 단정하지 않는다.
- Codex 응답을 받은 뒤 결과 파일을 저장하기 전에 운영체제가 강제 종료되는 아주 짧은 구간은 완전한 exactly-once를 보장할 수 없다.
- 실제 토큰 절감 효과는 아직 주장하지 않는다. Direct·Loop와 격리 벤치마크가 완성된 뒤 같은 모델·추론 조건에서 측정해야 한다.

공식 Codex 동작은 [인증](https://learn.chatgpt.com/docs/auth), [비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode), [CLI 옵션](https://learn.chatgpt.com/docs/developer-commands?surface=cli) 문서를 기준으로 구현했다.
