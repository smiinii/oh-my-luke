# 마일스톤 5: 로컬 프로젝트 스캐너

## 무엇을 만들었나

OML이 작업을 계획하기 전에 현재 프로젝트가 어떤 구조인지 같은 규칙으로 파악하는 스캐너를 만들었다. 이 단계는 AI를 호출하거나 빌드·테스트를 실행하지 않는다.

결과에는 다음 정보만 들어간다.

- Gradle, Maven, npm 같은 빌드 시스템
- Java, Kotlin, JavaScript, TypeScript 등 발견된 언어
- 소스와 테스트의 시작 폴더
- README 같은 중요한 설명 문서
- 안전하게 포함된 파일의 상대 경로, 크기, 종류
- 실행할 수 있는 빌드·테스트 명령 후보
- 제외한 항목 수와 탐색이 잘렸는지 알리는 사유

## 어떤 순서로 처리하나

```text
사용자가 프로젝트 경로 선택
→ 실제 프로젝트 폴더인지 확인
→ 상대 경로 이름순으로 파일 탐색
→ 비밀·OML 내부·Git 내부·생성물·바이너리 제외
→ 언어와 빌드 도구, 소스/테스트 폴더 탐지
→ 실행하지 않은 명령 후보 생성
→ 크기와 제외 사유가 담긴 프로젝트 프로필 반환
```

파일 이름순으로 탐색하기 때문에 같은 프로젝트와 같은 한도를 주면 매번 같은 프로필이 나온다. 한 폴더의 항목이 남은 한도보다 많으면 불확실한 일부만 고르지 않고 그 지점에서 잘림 처리한다. 명령 후보도 `./gradlew test` 같은 한 줄 문자열이 아니라 `./gradlew`, `test`처럼 분리된 인자 목록으로 만든다. 프로젝트 루트의 빌드 설정만 명령 후보가 되며, 이후 실제 실행 단계가 이 목록을 다시 권한 정책으로 검사할 수 있다.

개발 시 결과는 불변 `ProjectProfile`로 받는다. 경로는 운영체제 나열 순서가 아닌 정규화한 상대 경로순이다. 항목 수·포함 크기 합계·깊이로 탐색을 멈추면 `truncated`를 표시하고, 개별 대용량 파일만 제외한 경우는 `LARGE_FILE_SKIPPED`로 구분한다.

## 왜 필요한가

AI가 프로젝트 전체를 무작정 읽으면 관련 없는 생성 파일 때문에 토큰을 낭비하고 비밀 파일을 접할 위험이 생긴다. 스캐너는 먼저 작고 구조화된 지도를 제공해 이후 컨텍스트 선택과 작업 계획의 기준을 만든다.

다음 경계는 스캐너 자체에서 강제한다.

- `.git`, `.oml`, `node_modules`, `build`, `target` 등은 탐색하지 않는다.
- `.env`, 인증 설정, 개인 키와 공통 비밀 경로를 프로필에서 제외한다.
- 심볼릭 링크는 프로젝트 내부를 가리켜도 따라가지 않는다.
- 바이너리와 설정한 크기보다 큰 파일을 제외한다.
- 항목 수, 전체 포함 크기, 개별 크기, 폴더 깊이에 한도를 둔다.
- 파일 본문과 `package.json`의 실제 스크립트 값은 프로필에 넣지 않는다.

## 검증 근거

`ProjectScannerTest`가 다음 동작을 자동 검증한다.

- Gradle·Maven·npm 프로젝트와 언어 탐지
- 소스·테스트 폴더와 문서 탐지
- 구조화된 빌드·테스트 명령 후보
- 생성물, 민감정보, 바이너리, 대용량 파일 제외
- 프로젝트 밖 심볼릭 링크 미추적
- 생성 순서와 무관한 같은 결과
- 항목·전체 크기·깊이 한도와 잘림 사유
- 손상된 `package.json`의 안전한 처리
- 잘못된 프로젝트 경로와 한도 거부

전체 Gradle 테스트도 함께 실행해 기존 그래프·상태·권한·도구 동작이 깨지지 않았음을 확인한다.

## 현재 한계

- 현재는 Gradle, Maven, npm과 대표적인 7개 언어만 탐지한다.
- 소스·테스트 폴더는 널리 쓰이는 표준 이름을 기준으로 찾는다. 사용자 정의 레이아웃은 아직 설정할 수 없다.
- 프로필은 명령 후보만 제시한다. 빌드나 테스트 실행, 성공 판단, AI 컨텍스트 선택은 다음 단계의 책임이다.
- 파일 내용 기반 의존성 분석이나 의미 검색은 하지 않는다.
