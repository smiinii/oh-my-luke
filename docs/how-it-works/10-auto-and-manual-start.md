# 10. 자동·수동 선택: 실행 전에 방식을 정하기

`omluke start <job.json>`은 같은 작업표로 자동 또는 수동 실행 방식을 고르는 시작점이다. 통합 기획안의 11단계 Auto에 해당하며, 저장소에서는 Direct·Loop를 하나로 묶었으므로 마일스톤 10이다.

## 사용자가 보는 흐름

1. 목표·파일·검증 기준·한도가 담긴 JSON 작업표를 준비한다.
2. 터미널에서 시작하면 `1 자동 / 2 수동 / 0 취소`를 고른다.
3. 자동이면 정해진 규칙을 적용한다. 수동이면 가능한 모드를 한 번 더 고른다.
4. 선택 방식·모드·이유를 표시하고, 확정한 작업표와 함께 저장한 뒤 실행한다.
5. 나중에 확인하거나 재개할 때는 저장된 선택을 유지한다. 다시 묻거나 다시 고르지 않는다.

선택이 끝나기 전에는 AI 호출이나 파일 수정이 없다. 취소하거나 입력이 끝나면 실행을 만들지 않는다. 스크립트에서는 `--mode auto|direct|loop|workflow`를 명시하여 질문을 생략한다. 대화형 터미널이 아닌데 선택이 없으면 오류로 멈춘다.

## Auto가 판단하는 것과 하지 않는 것

Auto는 AI에게 “어떤 모드가 좋을까?”를 묻지 않는다. Java가 작업표에 이미 적힌 조건을 다음 순서로 확인한다.

| 이미 정한 조건 | 실행 방식 | 이유 |
| --- | --- | --- |
| Workflow 단계 선언이 있음 | Workflow | 사용자가 정한 경로를 보존 |
| 파일 적용 전 승인이 필요함 | Workflow | 승인 지점이 필요 |
| 승인 없는 단순 작업, 최대 시도 1회 | Direct | 한 번 시도하는 조건 |
| 승인 없는 단순 작업, 최대 시도 2회 이상 | Loop | 한도 안에서 재시도 가능 |

예를 들어 `maxAttempts: 3`인 단일 파일 작업은 Auto에서 Loop가 된다. 같은 작업에 `approvalBeforeApply: true`가 있으면 Workflow로 바뀌어 AI 제안과 파일 적용 사이에서 승인을 기다린다. 이미 선언한 Workflow는 간단해 보여도 축소하지 않는다.

목표 문장만 보고 난이도를 추측하거나 필요한 파일·검사를 만들어 주지는 않는다. 사용자가 작업표를 준비해야 하며, **가장 좋은 모드나 토큰 절약을 보장하는 기능은 아니다.** 반복해서 적던 실행 선택을 명확한 규칙으로 옮기는 편의 기능이다.

## 수동이면 어떤 선택이 가능한가

승인이나 Workflow 선언이 없는 작업은 Direct·Loop·Workflow 중 고를 수 있다. Direct는 시도 한도를 1로 낮춘다. Loop는 기존 한도를 유지하고, Workflow는 하나의 수정 단계를 고정 그래프로 감싼다.

승인이 필요하거나 이미 Workflow가 선언된 작업은 수동에서도 Workflow만 가능하다. 수동 선택을 이유로 승인이나 단계 조건을 버리지 않는다. 자동·수동 모두 한도를 늘리거나 모델을 바꾸거나 도구 권한을 넓히지 않는다.

기존 `run`과 `workflow` 명령도 그대로 사용할 수 있다. 이미 모드가 있는 기존 작업표를 명시적으로 실행하는 별도 진입점이며 새 질문을 하지 않는다.

## 왜 선택을 저장하나

선택 방식(`AUTO`/`MANUAL`), 실행 모드, 이유 코드, 규칙 버전 1을 확정 작업표와 같은 상태에 기록한다. 이후 원본 JSON을 고치거나 프로그램을 다시 켜도 진행 중 실행의 선택이 바뀌지 않는다.

`inspect`는 저장한 결과를 보여 주고, `resume`은 저장한 작업표로 같은 실행을 이어간다. 다시 선택하려면 새 실행을 시작한다. 실행 선택 메뉴는 Workflow의 적용 승인이나 도구 권한 승인과 서로 다른 절차다.

## 무엇으로 확인하나

- 선택 규칙: 같은 명시 조건이면 같은 모드·이유, 승인/선언 우선, 한도 증가 없음
- 수동 선택: Direct 시도 1회, Loop 한도 유지, Workflow 승인·경로 보존
- 입력 경계: 잘못된 옵션과 작업표 거부, 실제 파일 동일성으로 작업표·검증기 별칭 보호, 비대화형 무선택 오류, 취소·EOF에 실행 없음
- 저장·재개: 원본 작업표가 바뀌어도 확정 선택 유지, 별도 JVM의 실제 CLI로 승인·재개해도 메뉴나 Auto 재선택 없음
- 실행 연결: 기존 그래프 커널·가짜 AI로 성공·실패·승인 대기 흐름 검증
- 예제: 저장소의 시작용 JSON을 테스트로 읽어 실제 입력 형식 검증

관련 테스트는 `preset/Start*Test`, `preset/OperatorFileGuardTest`, `cli/StartPromptTest`, `cli/StartCliTest`, `cli/StartProcessTest`다. 실제 AI 없는 테스트는 제어 흐름을 확인하며, 특정 Codex 버전의 실제 연결이나 토큰 절감 효과를 입증하지 않는다.

## 현재 제한

여전히 작은 기존 파일과 사용자가 지정한 검증 기준이 필요하다. 자동 컨텍스트, 자연어 계획 생성, AI 제공자 자동 라우팅, 동적/병렬 그래프, 비교 실험과 공개 배포는 이번 구현에 포함하지 않는다.

사용량·시간·파일 충돌·권한 제한은 기존 실행과 같다. 승인 대기에도 시간 한도는 흐르며 실패 시 자동 롤백은 하지 않는다. 명령과 두 예제, 승인·재개 절차는 [자동·수동 시작 사용법](../start-usage.md)에 있다.
