# 마일스톤 6: 가짜 AI 실행기

## 무엇을 만들었나

실제 AI나 사용자 구독을 사용하지 않고도 AI가 포함된 그래프를 반복 테스트할 수 있는 가짜 실행기를 만들었다.

개발자가 다음처럼 예상 요청과 결과를 미리 정한다.

```text
예상 요청 1 → 성공 응답과 가짜 사용량
예상 요청 2 → 실패 사유와 가짜 사용량
```

가짜 실행기는 실제 모델처럼 자유롭게 답을 만들지 않는다. 들어온 요청이 다음 예상 요청과 정확히 같을 때만 미리 정한 결과를 반환한다.

## 어떤 순서로 처리하나

```text
그래프가 AI 노드 실행
→ 노드가 허용된 상태 키만 선택
→ 호출 ID·지시문·선택 문맥으로 요청 생성
→ 가짜 실행기가 다음 예상 요청과 비교
→ 일치하면 성공 또는 실패 결과 반환
→ 출력과 가짜 사용량을 그래프·정책에 기록
```

예상 요청과 다르면 해당 응답을 소비하지 않는다. 테스트를 고친 뒤 같은 요청을 다시 보내면 원래 응답을 받을 수 있다. 준비한 응답이 모두 소진된 경우도 별도 실패로 구분한다.

## 왜 필요한가

실제 AI부터 연결하면 테스트할 때마다 토큰과 시간이 들고 모델 응답이 달라져 그래프 문제와 모델 문제를 구분하기 어렵다. 가짜 실행기를 사용하면 다음을 비용 없이 고정해서 검증할 수 있다.

- AI 성공 후 다음 노드로 이동하는가
- AI 실패가 검사·수정 루프로 연결되는가
- 사용량 한도에서 정확히 멈추는가
- 중단 사유와 실패 반복이 같은 값으로 기록되는가
- AI에게 보내기로 한 문맥 외의 상태가 빠지는가

## 검증 근거

- `FakeAiRuntimeTest`: 정확한 순서, 불일치 시 미소비, 응답 소진, 불변 요청, 지문과 모델 불변식 검증
- `AiNodeTest`: 선택 문맥, 성공 출력, 구조화 실패, 사용량, 그래프 완료와 결정성 검증
- `ManagedRunServiceTest`: 가짜 AI 사용량이 체크포인트 정책 카운터와 사용량 한도에 반영되는지 검증
- 전체 Gradle 테스트와 macOS·Ubuntu CI로 기존 기능 회귀 검증

## 현재 한계

- 실제 AI, Codex CLI, 로그인 또는 네트워크를 사용하지 않는다.
- 응답은 사람이 테스트 코드에서 미리 작성해야 한다.
- 스크립트의 현재 위치는 메모리에만 있다. 가짜 실행기를 새로 만들면 첫 응답부터 다시 시작한다.
- 성공 출력은 현재 지정된 그래프 상태 키에 문자열로 저장한다. 큰 AI 출력의 아티팩트 분리는 실제 실행기 단계에서 정한다.
- 실제 토큰 수를 측정하지 않는다. `usage`는 정책 흐름을 검증하기 위해 스크립트에 적은 가짜 숫자다.
