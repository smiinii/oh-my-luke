# 마일스톤 6: 가짜 AI 실행기

## 무엇을 만들었나

실제 AI나 사용자 구독을 사용하지 않고도 AI가 포함된 그래프를 반복 테스트할 수 있는 가짜 실행기를 만들었다.

개발자가 다음처럼 예상 요청과 결과를 미리 정한다.

```text
논리 호출 1의 예상 요청 → 성공 응답과 가짜 사용량
논리 호출 2의 예상 요청 → 실패 사유와 가짜 사용량
```

가짜 실행기는 실제 모델처럼 자유롭게 답을 만들지 않는다. 실행·노드·단계를 조합한 논리 호출 ID와 요청 내용이 미리 정한 값과 정확히 같을 때 결과를 반환한다.

## 어떤 순서로 처리하나

```text
그래프가 AI 노드 실행
→ 노드가 허용된 상태 키만 선택
→ 실행별 호출 ID·지시문·선택 문맥으로 요청 생성
→ 가짜 실행기가 해당 호출 ID의 예상 요청과 비교
→ 일치하면 성공 또는 실패 결과 반환
→ 출력과 가짜 사용량을 그래프·정책에 기록
```

같은 논리 호출을 재시도하면 같은 결과를 다시 받는다. 따라서 결과 저장 직전에 중단돼도 재시도가 바뀌지 않고, 같은 스크립트로 실행기를 다시 만들어 중간 호출부터 재생할 수도 있다. 호출 ID는 같지만 요청 내용이 다르면 불일치, 등록되지 않은 호출 ID면 스크립트 소진 실패로 구분한다.

AI 노드는 실행 ID가 명확할 때만 실행기를 호출한다. 저장형 실행은 OML이 체크포인트의 실행 ID를 전달한다. 실행 ID 없는 상태는 특정 이름과 구분되므로 `local` 같은 유효한 이름도 명시적으로 전달하면 사용할 수 있다. 실행 ID 없는 단순 그래프 API에서는 서로 다른 작업의 결과가 섞이지 않도록 AI 호출을 거부한다.

## 왜 필요한가

실제 AI부터 연결하면 테스트할 때마다 토큰과 시간이 들고 모델 응답이 달라져 그래프 문제와 모델 문제를 구분하기 어렵다. 가짜 실행기를 사용하면 다음을 비용 없이 고정해서 검증할 수 있다.

- AI 성공 후 다음 노드로 이동하는가
- AI 실패가 검사·수정 루프로 연결되는가
- AI 호출이 끝난 뒤 누적 사용량이 한도에 도달하면 다음 노드 실행을 막는가
- 중단 사유와 실패 반복이 같은 값으로 기록되는가
- AI에게 보내기로 한 문맥 외의 상태가 빠지는가

## 검증 근거

- `FakeAiRuntimeTest`: 논리 호출 재생, 불일치, 미등록 호출, 실행기 재생성, 불변 요청, 지문과 모델 불변식 검증
- `AiNodeTest`: 선택 문맥, 성공 출력, 구조화 실패, 사용량, 그래프 완료와 결정성 검증
- `ManagedRunServiceTest`: 가짜 AI 사용량이 체크포인트 정책 카운터와 사용량 한도에 반영되는지 검증
- 전체 Gradle 테스트와 macOS·Ubuntu CI로 기존 기능 회귀 검증

## 현재 한계

- 실제 AI, Codex CLI, 로그인 또는 네트워크를 사용하지 않는다.
- 응답은 사람이 테스트 코드에서 미리 작성해야 한다.
- 성공 출력은 현재 지정된 그래프 상태 키에 문자열로 저장한다. 큰 AI 출력의 아티팩트 분리는 실제 실행기 단계에서 정한다.
- 실제 토큰 수를 측정하지 않는다. `usage`는 정책 흐름을 검증하기 위해 스크립트에 적은 가짜 숫자다.
- 사용량은 호출이 끝난 뒤 알 수 있다. 한 호출이 남은 한도보다 크면 그만큼 한도를 초과할 수 있으며 다음 노드부터 실행을 막는다.
- 실제 Codex 호출의 입력·출력 상한과 영속 멱등 저장은 [마일스톤 7](07-codex-cli-runtime.md)에 구현되어 있다. 가짜 실행기 자체는 계속 메모리 스크립트만 사용한다.
- 실제 제공자의 오류 원문은 그대로 저장하지 않고 허용된 실패 종류로 변환해야 한다.
