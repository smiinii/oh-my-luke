# 질문별 토큰 기록과 조회

#41의 개발 기능이다. 공개 `v0.1.0-rc.1`에 포함되었다는 뜻은 아니다. **OML에 제출한 작업표 한 건을 질문 한 건**으로 보여준다. Codex 앱이나 다른 터미널에서 주고받은 대화를 수집하는 기능은 아니다.

## 명령

```bash
omluke usage
omluke usage RUN_ID --details
omluke usage --format json
omluke usage --format csv
omluke usage RUN_ID --format csv --details
omluke --project /absolute/project usage
```

기본 화면은 `실행 ID | 질문 | 결과 | AI 시도 | 기록 토큰 | 대조`다. `--details`는 시도별 입력·캐시 입력·출력·추론 출력과 요청 모델을 보여준다. 기본 목록은 실행 ID 순이며 질문이 길면 화면에서만 줄인다. JSON·CSV에는 정제된 전체 목표 문구가 들어간다.

- JSON은 질문과 시도 상세를 함께 담는다. CSV 기본값은 질문별 한 행, `--details`는 시도별 한 행이다. 두 CSV의 합계를 다시 서로 더하지 않는다.
- JSON의 토큰 수는 십진수 문자열이다. 큰 정수를 JavaScript 숫자로 변환하면 정밀도를 잃을 수 있다. CSV도 스프레드시트에서 자동 숫자 변환하지 말고 텍스트로 가져온다.
- 누락은 JSON `null`, CSV 빈 필드, 화면 `확인 불가`다. 보고된 실제 0과 구별한다.
- 출력만 제공한다. 파일로 보관하려면 사용자가 셸 리디렉션 경로를 정한다. CSV의 수식 시작 문자는 작은따옴표로 무력화하고 제어문자·알려진 비밀 패턴을 정제한다. 내보내기 전 목표 문구의 개인정보는 직접 확인해야 한다.

## 어떤 기록을 대조하나

1. 현재 프로젝트의 `.oml/runs/<ID>/state.json` 및 실행 이벤트에서 작업표·writer 단계·상태를 읽는다.
2. 실행 ID와 원래 writer 노드·단계 번호로 기존 `AiInvocationId`를 재구성한다. Workflow의 `edit.writer`도 내부 호출에 사용한 `writer` ID로 연결한다.
3. 그 ID에 해당하는 `.oml/runtime/codex/invocations/<해시>.json`의 저장 결과만 읽는다. 모든 사용자 세션이나 다른 프로젝트는 검색하지 않는다.
4. 저장 토큰의 입력+출력과 해당 전이의 사용량을 대조한다. 전체 합계도 정책 누계와 맞는지 확인한다.
5. 같은 질문에 포함된 재시도를 합하고, 같은 저장 호출은 재개·조회 때 다시 더하지 않는다. 실패 응답도 사용량이 기록되어 있으면 포함한다.

이는 **기존 영속 기록의 읽기 뷰**다. 질문 원문·AI 답변·토큰을 새 DB나 별도 누계 파일에 중복 저장하지 않는다. 요청 모델은 확인할 수 있지만 실제 응답 모델 이름이라고 보증하지 않는다.

## 숫자를 믿어도 되는 범위

`기록 토큰 = 입력 + 출력`. 캐시는 입력의 하위 항목, 추론은 출력의 하위 항목이므로 다시 더하지 않는다. 합계는 큰 정수 연산을 사용한다.

`기록 일치`는 **조회한 저장 응답과 OML 이력의 대조가 맞는다**는 뜻이다. 계정 전체 소비량, 청구 금액, 구독 차감률, CLI 내부 자식 에이전트까지 빠짐없는 합계라는 뜻이 아니다. JSON의 `scope=provider-reported-only`, `childUsageCoverage=unverified`도 이 한계를 나타낸다.

- 사용량 필드 누락·형식 오류·중복 키·합계 불일치·범위 초과는 확정하지 않는다. 일부 호출만 확인되면 알려진 부분합과 `부분·확인 불가`를 함께 표시한다.
- 서로 다른 호출에 같은 세션 ID가 있으면 포크/중복 포함 여부를 추측하지 않고 해당 수치를 제외한다. 다른 세션 ID라고 자식 사용량의 완전성을 증명하는 것은 아니다.
- 실행 로그 누락·잘린 끝줄·체크포인트 백업 복구·노드 재실행에는 미기록 소비 가능성을 표시한다. 프로세스가 결과 저장 전에 죽었을 때 이미 소비한 토큰을 복원할 수는 없다.
- 이 어댑터는 프롬프트 한 건을 `exec`로 보낸다. 식별할 수 없는 여러 `turn.completed`를 무작정 합산하지 않는다. 필수 네 토큰 항목 중 하나라도 없으면 세부 값을 0으로 채우지 않고 사용량을 미확인으로 둔다. 구버전/다른 형식의 부분 필드 복원은 후속 과제다.
- 이 기능은 로컬 정규화 저장 결과와 이력을 대조한다. 원본 JSONL 전체를 새로 보관하거나 서버 청구 원장을 검증한 것은 아니다. 수동으로 복사·조작한 기록을 암호학적으로 인증하지 않는다.

형식 근거: [Codex 비대화형 JSONL 출력](https://learn.chatgpt.com/docs/non-interactive-mode#make-output-machine-readable). 이 기능의 합성 검증은 토큰 절감 실험이나 실제 유료 AI 호출 실험이 아니다.

## 결과와 프로젝트 경계

- `완료 · 검증 전`: AI 응답은 성공했으나 작업의 최종 검증 통과는 아직 아니다.
- `통과`: 그래프가 검증 성공 경로의 종료 노드에 도달했다.
- 진행 중·승인 대기·실패/중단·취소는 별도로 표시한다. 실행 중 잠금이 잡혀 있으면 불안정한 스냅샷 대신 조회를 거부한다.

기록 범위는 [기존 프로젝트 루트 규칙](execution-settings.md#기록-폴더-결정)을 그대로 따른다. 전역/프로젝트별 하네스 선택 범위와는 별개이며 홈을 자동 기록 프로젝트로 쓰지 않는다. 조회는 설정이나 기록 디렉터리를 생성·복구·삭제하지 않는다. 기존 실행 잠금만 잠시 잡고 해제한다.

기록 경로의 심볼릭 링크와 Unix 하드 링크를 거부한다. 실행당 상태/백업/이벤트 파일 각각 16 MiB, 호출 결과 8 MiB, 한 번의 목록 500건을 넘으면 조용히 생략하지 않고 조회 범위를 제한하거나 미확인으로 표시한다. 같은 OS 사용자 권한의 악성 프로세스가 경로를 동시에 바꾸는 공격까지 완전 격리하는 기능은 아니다.
