# Security

## 기본 원칙

- 프로젝트 내부의 허용된 경로만 수정한다.
- 경로를 정규화한 뒤 `..`와 심볼릭 링크 탈출을 검사한다.
- 셸 명령과 인자를 분리하고 신뢰한 절대 실행 파일·전체 인자 목록으로 검증한다.
- `.env`, 키, 인증서, AI CLI 인증 파일을 컨텍스트와 로그에서 제외한다.
- 외부 발행, 배포, 삭제, 프로젝트 밖 쓰기는 정확한 작업·경로·실행 범위에 결속된 사용자 승인을 요구한다.
- AI가 권한, 완료 조건, 반복 제한을 변경하지 못하게 한다.
- 액세스 토큰, API 키, 세션 쿠키를 상태와 이벤트에 기록하지 않는다.

## 초기 기본값

- 읽기 중심
- 프로젝트 내부 쓰기만 허용
- 외부 변경 작업은 차단
- 결정론적 검증 통과 전 성공 처리 금지

## MVP 로컬 경로 위협 모델

- 실행을 시작할 때 이미 존재하는 심볼릭 링크가 프로젝트 밖을 가리키면 읽기와 쓰기를 거부한다.
- 최종 파일의 심볼릭 링크 추적을 금지하고, 임시 파일은 운영체제가 충돌 없이 새로 생성한다.
- 현재 MVP는 같은 사용자 권한의 악의적인 별도 프로세스가 경로 검사 직후 디렉터리를 바꿔치기하는 경쟁 공격까지 방어하지 않는다.
- 실제 외부 명령 실행을 추가하기 전에는 디렉터리 핸들 기반 상대 I/O 또는 운영체제 샌드박스로 이 경쟁 창을 제거해야 한다.
- 외부 프로세스가 `.oml`의 정책, 체크포인트, 이벤트 파일을 쓰지 못하게 별도 권한 경계를 적용해야 한다.
- 지원 운영체제별로 프로젝트 경계 밖 쓰기를 차단하는 샌드박스를 검증해야 한다.
- 위 조건을 보장할 수 없는 환경에서는 외부 명령 실행을 거부하는 fail-closed 방식으로 동작해야 한다.
