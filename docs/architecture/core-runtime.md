# 코어 실행과 복구

그래프·관리 런타임·상태 저장·정책을 수정할 때 읽는 기술 계약이다. 전체 구성은 [아키텍처 안내](../architecture.md), 권한과 OS 격리는 [보안 문서](../security.md)를 따른다.

## 그래프 커널 계약

- `Node`는 읽기 전용 `NodeContext`를 받고 `Outcome`과 `StatePatch`를 반환한다. 상태 변경분은 `GraphRunner`만 적용한다.
- 실패 노드는 안정적인 `FailureInfo`(종류·코드·원인)를 선택적으로 반환한다. 관리 런타임은 이 정보가 있을 때 동일 실패를 누적한다.
- `Node.fingerprint()`는 노드 종류, 동작 버전과 결과에 영향을 주는 설정을 나타낸다.
- 모든 실행 노드는 각 `Outcome`에 대해 정확히 하나의 `Condition`이 일치해야 한다. 겹치거나 비어 있는 분기는 실행 전에 거부한다.
- 각 이동은 상태 변경분, 적용 후 상태, 다음 노드와 선택 이유를 `TransitionEvent`에 기록한다.
- 일괄 실행과 저장형 단계 실행은 검증·그래프 인덱스를 한 번 준비해 재사용한다.
- 단계별 불변 이력은 영속 추가 리스트로 연결해 이전 경로와 이벤트 전체를 매번 복사하지 않는다.
- 상태와 이벤트의 맵은 불변이며 입력 및 상태 변경분의 반복 순서를 보존한다.
- 종료 노드 도착은 커널의 `COMPLETED`, 최대 단계 도달은 `STEP_LIMIT_REACHED`다. 커널 종료만으로 작업의 검증 성공을 의미하지 않는다.
- 순환이 있는 그래프는 양수인 최대 단계 한도가 없으면 실행 전에 거부한다.

## 노드 하나를 실행하는 순서

`ManagedRunService`가 순수한 `GraphRunner` 바깥에서 파일 저장과 수명주기를 조정한다. 그래프 코어에는 파일 시스템이나 CLI 의존성이 들어가지 않는다.

```text
ManagedRunService
├── GraphRunner       한 단계 실행
├── CheckpointStore   state.json 원자적 교체와 백업 복구
├── EventLogStore     events.jsonl 추가 기록
└── HandoffStore      handoff.md 원자적 교체
```

```text
READY 체크포인트
  → NODE_STARTED 체크포인트 저장
  → NODE_STARTED 이벤트 기록
  → 노드 실행
  → 정책 카운터·실패·상태 지문 갱신 및 판정
  → 새 READY 체크포인트 저장
  → NODE_COMPLETED 이벤트 기록
  → POLICY_EVALUATED 이벤트 기록
```

## 저장 형식과 입력 검증

- `state.json`은 스키마 버전과 그래프 구조·노드 동작 지문의 SHA-256 서명을 가진다.
- 시작 시 고정한 정책 설정, 현재 카운터, 반복 실패·무진전 횟수와 마지막 정책 판정도 함께 저장한다.
- 체크포인트 스키마 2는 기존 스키마 1을 제한 비활성화 상태로 읽어 올린다.
- 지원하지 않는 스키마는 백업으로 숨기지 않고 명시적으로 거부한다. 저장할 때도 현재 구현이 읽을 수 있는 버전만 허용한다.
- 파일 내부 `runId`와 실행 디렉터리 ID가 다르면 상태 혼합으로 보고 거부한다.
- 프로젝트 실제 경로를 기준으로 심볼릭 링크 탈출을 검사하고 임시 파일은 충돌 없는 새 파일로 생성한다.

## 중단·손상·동시 실행 복구

- 손상된 기본 체크포인트는 마지막 `READY` 백업이 있을 때만 복구한다. `NODE_STARTED` 상태는 안전 백업을 덮어쓰지 않는다.
- 중단된 노드는 마지막 안전 체크포인트의 상태로 다시 실행한다. 재개할 그래프의 구조·노드 동작 서명이 다르면 실행하지 않는다.
- 이벤트 로그는 UTF-8 문자 중간을 포함해 완전히 기록되지 않은 마지막 JSONL 줄만 제거한다. 정상 접두사는 임시 파일을 거쳐 원자적으로 교체하며 중간 손상은 오류다.
- 취소 이벤트를 체크포인트보다 먼저 기록하므로 취소 상태 파일이 손상되어도 노드를 다시 실행하지 않는다.
- 체크포인트 저장 뒤 완료 이벤트 기록 전에 종료되면 `inspect`는 체크포인트 전이 이력으로 완전한 읽기 뷰를 제공한다. 다음 변경 작업은 누락 이벤트를 영구 기록한다.
- 실행 ID별 운영체제 파일 잠금으로 두 프로세스가 같은 노드를 동시에 실행하지 못하게 한다.

## 정책 판정과 카운터

정책 엔진은 그래프 코어 밖에서 Java 값으로 판정한다. 완료 평가기는 명령을 직접 실행하지 않고, 검증기가 제공한 종료 코드·파일 존재·중대 오류 수·요구사항 충족 사실을 검사한다.

| 정책 결과 | 의미 |
| --- | --- |
| `SUCCESS` | 실제 완료 사실이 `all` 또는 `any` 조건을 충족 |
| `LIMIT_REACHED` | 반복·경과 시간·노드/도구 호출·사용량 한도 도달 |
| `BLOCKED` | 같은 실패·무진전·권한 또는 경계 위반 등으로 중단 |
| `CANCELLED` | 사용자 취소 |
| `CONTINUE` | 위 조건에 해당하지 않아 실행 가능 |

- `ManagedRunService`는 노드마다 반복·노드 호출 수와 상태 지문을 갱신하고 한도에 도달하면 다음 노드를 실행하지 않는다. 재개 직전에도 시간 제한을 검사한다.
- AI 호출은 도구 호출로 세지 않으며 `usage`만 별도로 보고한다. 노드 호출 수는 그래프 정책이 계산한다.
- 사용량은 호출 결과를 받은 뒤 누적된다. 남은 한도를 넘는 호출 자체를 미리 차단하지는 못하고 이후 노드부터 중단한다.
- `inspect`는 마지막 정책 결과·이유·재개 가능 여부·카운터를 표시한다. 커널의 `iterations`는 노드 시도 수이며 프리셋의 AI 시도 수와 다르다.
- 프리셋은 시도·동일 검증 실패·같은 제안 횟수를 별도로 저장한다. 사용자 결과 `PresetResult`와 커널 상태·정책 결과를 혼동하지 않는다.

## 도구 노드와 외부 부작용

```text
FileToolNode / ProcessToolNode
  → ToolPermissionEvaluator
  → 허용된 구조화 도구 실행
  → 아티팩트 저장
  → ExecutionMetrics(toolCalls, usage)
  → 그래프 전이와 정책 카운터
```

- 도구 노드는 성공, 승인 필요, 영구 차단, 비정상 종료, 시간 초과를 구조화된 결과와 `FailureInfo`로 구별한다.
- 파일 본문과 프로세스 출력은 `.oml/runs/<run-id>/artifacts/`에 저장하고 상태에는 경로·종료 코드·권한 이유·크기 같은 메타데이터를 남긴다.
- 노드의 외부 부작용은 일반적으로 정확히 한 번을 보장할 수 없다. 파일 도구는 작업 ID에 결속된 최초 체크포인트와 현재 완료 상태 검증으로 성공한 변경의 재실행을 멱등 처리한다.
- 프로세스처럼 외부 효과가 있는 도구에는 별도의 멱등성 키나 사전 조건이 필요하다. 승인·복구·잠금·OS 경계의 상세 기준은 [보안 문서](../security.md)에 있다.

## CLI 재개와 검증 근거

독립 CLI는 저장된 `TaskSpec`으로 Direct·Loop 그래프를 재구성한다. 임의 Java 노드 그래프는 `GraphResolver` 등록이 필요하다. `inspect`와 `cancel`은 저장 파일만으로 동작하며, 사용 절차와 제한은 [프리셋 사용법](../preset-usage.md)을 따른다.

- [관리 실행 테스트](../../src/test/java/io/ohmyluke/runtime/ManagedRunServiceTest.java): 중단·재개·정책 연결
