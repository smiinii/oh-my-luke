# ADR 0006: Codex CLI Adapter Boundary

- Status: Accepted
- Date: 2026-08-29

## Context

OML의 첫 실제 AI 실행기는 사용자가 이미 로그인한 Codex CLI다. 사용자의 기본 모델 선택권을 보존하면서도 인증정보 노출, 원본 프로젝트 변경, 중복 호출과 관측 불가능한 토큰 추정을 막아야 한다.

## Decision

- `CodexCliRuntime`을 `AiRuntime` 뒤의 전용 BYOR 어댑터로 구현한다.
- 설치·로그인 확인은 공식 `--version`과 `login status` 명령만 사용하고 인증 파일을 읽지 않는다.
- 모델과 추론 강도는 기본적으로 사용자 Codex 설정을 상속하며, 명시한 실행에서만 공식 CLI 옵션으로 재정의한다.
- OML은 모델 이름 허용 목록을 복제하지 않고 입력 경계만 검증한다.
- 실제 AI 실행은 민감 파일을 제외한 임시 프로젝트 사본을 기본 작업공간으로 사용하고 Codex 셸 샌드박스를 읽기 전용으로 고정한다. 이를 Codex의 모든 읽기 통로를 막는 기밀성 경계로 간주하지 않는다.
- 프롬프트는 표준입력, 결과는 공식 JSONL로 전달하고 `turn.completed.usage`를 직접 측정한다.
- 완료 결과는 논리 호출 ID와 요청·런타임 설정 지문에 결속해 원자적으로 저장하고 동시 실행을 잠근다.
- 기본 CI는 실제 계정을 사용하지 않으며 저장 로그인을 쓰는 스모크 테스트는 명시적으로 활성화한다.

## Consequences

- 사용자는 별도 OML API 키 없이 자신의 저장된 Codex 로그인을 사용할 수 있다.
- 모델을 생략하면 사용자의 기존 Codex 선택을 OML이 덮어쓰지 않는다.
- 테스트는 가짜 CLI로 결정적으로 실행되고 필요할 때만 실제 저장 로그인으로 연결을 확인한다.
- `login status` 성공만으로 저장 인증 방식은 구분하지 않으며, `inherit`의 실효 모델·추론 값과 CLI 버전은 결과 지문에 포함하지 않는다.
- 이번 단계의 Codex는 원본 파일을 수정하지 못한다. 변경 반영은 Direct·Loop 프리셋과 구조화 도구 연결에서 별도로 설계한다.
- 제공자 응답 이후 결과 저장 전 강제 종료 구간은 완전한 exactly-once를 보장하지 못한다.
