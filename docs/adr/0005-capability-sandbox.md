# ADR 0005: Capability Policy and Sandboxed Tools

- Status: Accepted
- Date: 2026-08-28

## Context

정확한 실행 파일과 전체 인자 목록을 미리 등록하는 방식은 새로운 언어와 개발 도구가 추가될 때마다 OML 설정을 바꿔야 하며 AI의 유연성을 지나치게 제한한다. 반대로 모델이 명령의 안전성을 스스로 선언하게 하면 하위 프로세스가 선언과 다른 동작을 수행할 수 있다.

## Decision

- 정책은 명령어 이름이 아니라 `ALLOW`, `ASK`, `DENY` 능력과 정확한 대상을 판정한다.
- `DENY` 불변식은 승인과 프로젝트 자율 실행으로도 해제할 수 없다.
- 프로세스 경계는 모델 판단이 아니라 macOS Seatbelt 또는 Linux bubblewrap이 강제한다.
- 프로세스 승인은 실제 실행 파일과 전체 구조화 입력의 결정적 해시에 결속한다.
- 프로세스는 민감 파일을 제외한 일회용 프로젝트 사본에서 실행한다.
- macOS는 사용자 데이터 root 읽기와 자식 생성을 거부하고, Linux는 bubblewrap PID namespace의 PID 1 감독을 사용한다.
- 지속할 파일 변경은 구조화 파일 도구와 복구 체크포인트를 통해서만 수행한다.
- 운영체제 샌드박스를 검증할 수 없으면 프로세스 실행을 거부한다.

## Consequences

- 프로젝트 내부의 되돌릴 수 있는 작업은 승인 팝업 없이 실행할 수 있다.
- 새로운 도구를 쓰기 위해 전체 명령 목록을 미리 등록할 필요가 없다.
- 사용자 승인 범위와 실행 사실을 재현 가능하게 기록할 수 있다.
- 프로세스가 만든 변경은 원본 프로젝트에 자동 반영되지 않는다.
- 동일 파일 작업 ID의 최초 체크포인트는 불변이며 HMAC 검증에 실패하면 복구 전에 중단한다.
- Windows 프로세스 실행과 도메인 단위 네트워크 제한은 별도 네이티브 경계가 필요하다.
