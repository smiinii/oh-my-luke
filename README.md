# Oh My Luke

> 쓰던 AI는 그대로, 작업은 검증하고 이어서.

Oh My Luke(OML)는 사용자가 이미 쓰는 AI CLI를 연결해 개발 작업의 실행·검증·재시도·재개를 관리하는 **Java 기반 로컬 AI 하네스**입니다.

불필요한 AI 호출과 반복 입력을 줄이면서, 사용자가 정한 완료 조건에 도달하도록 돕는 것을 목표로 합니다. 현재는 Codex CLI를 연결한 개발 단계입니다.

## 왜 만드나요?

AI에게 개발 작업을 맡기는 과정에는 결과 확인, 실패 원인 전달, 재시도와 중단 후 재개가 필요합니다. OML은 이 과정을 명확한 규칙과 기록으로 관리합니다.

- **결과 검증:** AI의 완료 선언 대신 지정한 검사 결과로 성공을 판정합니다.
- **제한된 재시도:** 재시도 가능한 실패만 반복하고, 같은 실패가 계속되면 멈춥니다.
- **상태 보존:** 작업표·진행 상태·실패 정보를 저장해 중단 후 이어서 실행합니다.
- **효율 측정:** 호출 횟수와 보고된 토큰 사용량을 기록해 비교 실험의 기반을 만듭니다.

토큰 절감은 목표이며, 직접 AI CLI를 사용하는 방식보다 효율적인지는 아직 검증하지 않았습니다. 성공률과 사용량을 함께 비교할 [실험 계획](docs/experiment.md)을 따릅니다.

## 어떻게 동작하나요?

현재는 사용자가 지정한 작은 기존 파일 하나를 수정하고 검증합니다.

1. **작업 정의:** JSON 작업표에 목표·대상 파일·검증 기준·실행 모드·한도를 지정합니다.
2. **수정안 생성:** AI가 파일의 수정안을 제안합니다.
3. **검사 후 적용:** OML이 경로·권한·파일 충돌을 확인하고 복구 지점을 만든 뒤 수정안을 적용합니다.
4. **결과 검증:** Java 또는 사용자가 지정한 검증 명령으로 결과를 확인합니다.
5. **종료 또는 재시도:** 검증에 통과하면 성공하고, 실행 모드와 실패 원인에 따라 재시도하거나 중단합니다.

AI는 수정안을 만드는 작성자이며, 현재 검사자는 Java와 고정 검증 명령입니다. 별도의 AI 검사자는 현재 호출하지 않습니다. 성공은 `result=SUCCEEDED`로 확인하며, 내부 그래프의 `COMPLETED`는 작업 성공과 다릅니다.

## 왜 그래프 기반인가요?

작업을 **단계(노드)**, 결과에 따른 이동을 **경로(엣지)**, 진행 정보를 **상태**로 표현합니다. 그래프 커널이 다음에 무엇을 실행하고 언제 반복·종료할지 결정합니다.

| 실행 방식 | 동작 | 상태 |
| --- | --- | --- |
| Direct | OML이 AI를 한 번 호출하고 유효한 수정안을 적용·검증한 뒤 종료 | 구현 |
| Loop | 같은 흐름에서 재시도 가능한 실패만 작성 단계로 되돌림 | 구현 |
| 정적 Workflow | 여러 작업 단계에 조건 분기와 사람 승인을 연결 | 개발 예정 |

**하네스는 작업 환경을 관리하는 역할이고, 그래프는 그 흐름을 구현하는 구조이며, 루프는 실행 패턴입니다.** Direct와 Loop는 이미 구현한 하나의 그래프 커널과 상태 저장·재개 기능을 공유합니다. Workflow를 별도 엔진으로 만들지는 않습니다.

## 현재 범위와 한계

| 구분 | 현재 상태 |
| --- | --- |
| AI 연결 | Codex CLI의 저장된 로그인 사용, 실행별 모델·추론 강도 선택 |
| 파일 수정 | 기존 UTF-8 파일 하나, 64 KiB 이하 |
| 실행 관리 | 작업표 기반 실행, 상태 확인·취소, 저장된 작업표로 재개 |
| 프로젝트 스캔 | 별도 Java API로 제공하며 `run`의 자동 컨텍스트 선택에는 아직 미연결 |
| 남은 작업 | 정적 Workflow, 자동 컨텍스트·모드 선택, 비교 실험, 공개 배포 |

- 지정한 검사를 통과한 것과 모든 요구사항의 정확성을 증명한 것은 다릅니다. 검증 기준은 사용자가 정합니다.
- 실패 시 이미 적용한 파일을 자동으로 되돌리지 않습니다. 상태·복구 지점과 [재개 절차](docs/preset-usage.md)를 확인해야 합니다.
- 외부 명령은 운영체제와 샌드박스 제약을 받습니다. macOS의 전체 빌드·자식 프로세스 실행과 Windows 프로세스 검증은 아직 지원하지 않습니다. 모든 프로젝트의 테스트가 바로 실행되는 것은 아닙니다.
- 시간·사용량 한도는 노드 경계에서 검사하므로 한 호출만큼 초과할 수 있습니다. 제공자가 보고하지 않은 토큰을 0으로 간주하지 않습니다.

## 개발 환경에서 시작하기

현재 개발 빌드에는 **JDK 21**이 필요합니다. Gradle은 저장소의 Wrapper를 사용하므로 별도로 설치할 필요가 없습니다.

저장소 루트에서 기본 테스트를 실행합니다. 기본 테스트와 CI는 실제 AI를 호출하지 않습니다.

```bash
./gradlew test
```

Windows에서 기본 테스트 명령은 다음과 같습니다. 파일·프로세스 도구의 운영체제 지원 범위는 [보안 문서](docs/security.md)를 확인하세요.

```powershell
.\gradlew.bat test
```

실제 파일 수정은 [개발용 Direct·Loop 실행 예제](docs/preset-usage.md)를 따라 작은 별도 프로젝트에서 확인하세요. Codex CLI 설치·로그인이 필요하며, 실제 호출에는 사용자의 계정 사용량이 적용됩니다. 실행·모델 선택·검증·재개 명령은 해당 문서에 있습니다.

## 기술 기준

Java 21 LTS · Gradle Kotlin DSL · JUnit 5 · 단일 그래프 커널. Spring Boot나 데이터베이스 없이 로컬에서 동작합니다. 그래프 코어는 AI·네트워크 없이 테스트합니다.

## 배포 계획

현재는 소스에서 빌드하는 개발 단계이며, 아래 설치 경로는 공개 배포 계획입니다.

- OML 전용 Java 런타임을 포함한 운영체제별 패키지를 GitHub Releases로 제공해, 사용자가 OML 실행을 위해 Java나 Node.js를 따로 설치하지 않도록 할 예정입니다.
- 설치 검증 후 macOS는 Homebrew, Windows는 WinGet을 연결하고, Linux는 우선 GitHub Releases를 사용합니다.
- npm 배포는 계획하지 않습니다. 실제 설치 테스트를 통과한 운영체제만 지원 대상으로 표시합니다.

연결할 AI CLI의 설치·로그인 요구사항은 별도입니다. 공개 전에는 설치·첫 실행·업데이트·삭제 절차를 실제 환경에서 검증하고 안내합니다.
